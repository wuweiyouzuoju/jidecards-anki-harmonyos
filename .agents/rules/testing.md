# 验证约定

唯一命令与能力说明见 [验证说明](../../docs/development/verification.md)。

- `npm test -- <领域>` 是局部任务的验证入口；也可直接运行受影响的测试文件。`npm test` 保留自动发现全部 `tools/tests/*.test.mjs` 的完整回归入口。
- 新业务规则直接 import 真实模块执行。平台适配可注入可控依赖；页面源码提取测试仅作现有过渡保障，不作为新增业务测试的首选。
- 保留协议、资源和依赖方向等必要静态检查；不锁死方法位置、注释或等价语法。
- 日常任务按[分级验证](../../docs/development/verification.md#按变更路径选择验证)选择检查，不默认运行全量 `verify`；完整入口和 CI 的失败语义不变。
- 需要设备验收或用户要求体验时覆盖安装；不得 uninstall。设备操作遵循用户的操作权约定，没有验证的交互简短记录。
- 不追求测试数量。真实 bug 的回归应能抓住故障；文案、图标、颜色和简单间距不专门新增锁死措辞或等价语法的测试。
- 不因任务收尾重复刚通过的检查；只在相关输入变化、失败修复或仍有具体疑点时重跑。局部检查按实际范围报告，不写成全量通过。
- 共享工作树失败执行[协作规则](../../docs/development/coding-agent.md#多-agent-协作)的归因与交接，不擅自修补其他任务、削弱测试或修改基线来凑绿。
