# `tools/` 与 `.github/` 局部规则

## 适用路径

本规则适用于验证脚本、构建脚本、发布脚本、测试注册、CI 工作流和工具说明改动。

## 修改边界

- 工具脚本必须从仓库根目录可重复运行，失败返回非零，并说明它实际验证了什么。
- `tools/test.mjs` 和 `tools/test-suites.mjs` 只负责发现或筛选测试；完整测试不得依赖手写文件总表。
- 新增验证门禁必须同步说明入口、失败含义、环境前提和不能替代的验证范围。
- CI 只能调用仓库已有的稳定入口；不要在工作流中复制一套只在 CI 有效的隐式逻辑。

## 验证

- 运行受影响工具的行为测试，必要时实际执行其命令；测试发现、领域筛选和计划脚本优先运行对应专项或 `npm test -- tooling`。
- 不重复执行 `npm test` 与包含同一全量测试的 `verify -- repo`；普通工具修改不自动全仓回归。
- 修改完整验证入口、原生/HAP 调用链、依赖或 SDK 时，按[分级验证](../../../docs/development/verification.md#按变更路径选择验证)补集成检查；CI 保留已有完整门禁。
