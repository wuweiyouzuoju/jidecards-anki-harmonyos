# `tools/` 与 `.github/` 局部规则

## 适用路径

本规则适用于验证脚本、构建脚本、发布脚本、测试注册、CI 工作流和工具说明改动。

## 修改边界

- 工具脚本必须从仓库根目录可重复运行，失败返回非零，并说明它实际验证了什么。
- `tools/test.mjs` 和 `tools/test-suites.mjs` 只负责发现或筛选测试；完整测试不得依赖手写文件总表。
- 新增验证门禁必须同步说明入口、失败含义、环境前提和不能替代的验证范围。
- CI 只能调用仓库已有的稳定入口；不要在工作流中复制一套只在 CI 有效的隐式逻辑。

## 验证

- 工具或 CI 改动至少运行 `npm run verify -- repo`。
- 修改测试发现、领域筛选或验证脚本时，补跑 `npm test`，必要时实际执行受影响命令。
- 修改原生或 HAP 调用链时，按对应目录规则补齐 `native` 或完整 `verify`。
