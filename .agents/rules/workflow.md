# 按风险执行的工作流

所有风险级别都先执行 [同类变更闭环](../../docs/development/coding-agent.md#同类变更闭环)：按语义发现同类和散写实现，确认责任入口与保留差异，再修改并验证全部受影响调用。查全影响范围不要求扩大用户目标或引入额外抽象。

- 局部文案/样式：读相关实现，检查资源、引用和最终效果；默认不全量测试或构建，不为单句措辞和等价样式新增形状测试。
- 业务行为：沿调用点核对输入、状态所有权和失败路径；运行受影响测试，真实 bug 或新行为需要时补回归。新增类型、组件或平台 API 时补一次增量 HAP。
- 跨模块/架构：先说明减少的变更成本，按模块逐步实施并合并受影响检查；大范围集成、协议或构建输入升级按[分级验证](../../docs/development/verification.md#按变更路径选择验证)完成完整验收。设备行为单独记录。
- 检查通过且相关输入未变时复用结果；仅有补充文档或新的对话不重跑业务、原生和 HAP。多任务共享目录先检查本任务与公共依赖，一批改动稳定后集中完整验收。

不强制提交、上传或独立分支；保留已有未提交改动。用户要求的完整改造可以重写确需替换的模块，但必须保留行为并验证。
包名、签名身份、用户数据和锁定的 Anki 协议是稳定边界。配置位置可因明确任务迁移，迁移不得改变身份或破坏覆盖安装。

失败先按[协作规则](../../docs/development/coding-agent.md#多-agent-协作)归因：修复本任务引起的问题，其他任务或未就绪依赖交由负责人处理；不为过关补占位实现。无法验证时报告具体阻碍，不把跳过等同通过。
用户可见操作失败须有可见结果。不要为无关代码补注释、全量改名或增加兼容垫片。
