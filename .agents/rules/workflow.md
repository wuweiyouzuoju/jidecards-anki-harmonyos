# 按风险执行的工作流

- 局部文案/样式：读相关实现，修改后验证相关资源/界面。
- 业务行为：沿调用点核对输入、状态所有权和失败路径；增加或调整行为回归，最终跑全部 Node 测试。
- 跨模块/架构：先说明为什么减少未来变更成本，按模块逐步实施；全部 Node、相应 Rust 测试和完整 HAP 构建后交付。UI/IO 行为做设备验收。

不强制提交、上传或独立分支；保留已有未提交改动。用户要求的完整改造可以重写确需替换的模块，但必须保留行为并验证。
包名、签名身份、用户数据和锁定的 Anki 协议是稳定边界。配置位置可因明确任务迁移，迁移不得改变身份或破坏覆盖安装。

失败先检查错误与依赖，修正后重试；无法验证时报告具体阻碍，不把跳过等同通过。
用户可见操作失败须有可见结果。不要为无关代码补注释、全量改名或增加兼容垫片。
