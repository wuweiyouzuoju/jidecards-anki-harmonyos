# 项目知识维护

PROJECT_CONTEXT.md 只承担入场索引：全局不变量、唯一事实来源、任务到领域文档/实现/验证的路由。
领域说明放 docs/development，按需读取；不要把每次修复记录追加到入口。
版本/SDK/发布开关从配置读取，测试数量和验证日期写任务报告或发布记录，不维护多份“当前值”。
项目间对照只维护领域映射与事实来源，功能状态复用 `docs/FEATURE_STATUS.md` 及当前领域说明，不再维护另一份缺口矩阵。已完成项从当前待办移除；历史审计明确标注当时范围并链接当前拥有者，不能仅在顶部勘误后仍把过期结论写成当前状态。源码接通、主机验证、编译和设备验收分别记录，设备待验不等于功能未实现。
修改模块边界时更新对应领域文档与入口路由；历史计划不能替代源码现状。文档链接由仓库测试验证。
设备视觉与交互结论分别标注源码接线、安装记录、运行证据和用户实际使用反馈。用户明确确认已生效的行为应进入所属领域文档；历史未验收记录或 SDK 缺少显式参数，不能作为否定该行为的证据。某项反馈未覆盖的其他能力保持单独核对，不扩大为全部完成或全部未实现。

## 过期知识核查与修复

遇到文档、注释、功能清单、旧报告或测试假设可能与现状冲突时，核查与修复是当前任务的一部分。按本次依赖链查清相关事实和同类引用，让后续编程 Agent 能直接找到可信入口；不扩大为无关的全仓重写。

1. **确认事实与范围。** 沿真实入口、调用链、配置/发布开关和相关测试核对现状，检查未提交改动和证据对应的输入。区分当前工作树、已发布版本、历史快照，以及源码接通、主机验证、编译、设备表现和用户实际反馈；日期较新或测试曾通过不能自动证明结论仍有效。
2. **查全同类矛盾。** 用能力名称、代码符号、配置键、旧结论和替代名称搜索当前索引、领域文档、规则、注释与测试；沿引用追到唯一事实拥有者。不能只改发现的那一处，或只查已知正确的入口。
3. **按根因解决。** 说明过期的是文档、实现、测试假设还是验证证据。文档漂移直接纠正当前正文、待办和入口；历史材料保留当时范围与证据并指向当前拥有者。测试失配先核对行为契约，再用真实实现的等价行为验证替换旧假设，不削弱断言。实现故障按任务范围修复，不能为迎合旧说明改坏当前行为；共享工作树仍须保留他人未完成工作。
4. **防止重复漂移。** 合并重复的当前状态，复用源码、配置和领域文档的单一事实来源。对可机械识别的版本、字段、发布开关、链接与依赖关系复用或补充自动检查；自然语言的正确性仍须核查，不能把某句话或符号出现当作实现、验收或语义正确的证明。
5. **验证后交接。** 运行与改动风险匹配的最少检查，记录查找范围、已消除的矛盾、保留的历史边界及实际验证。只有当前源码、测试和会话证据仍无法确定且会影响正确性时，才向用户提出具体问题；先完成不依赖答案的部分，说明冲突证据与阻碍，不能把未解决事项写成已完成，也不能只留一句“可能过期”让下一位 Agent 重查。
