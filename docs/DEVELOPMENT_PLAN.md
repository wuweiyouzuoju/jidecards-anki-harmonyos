# jidecards 开发状态与后续工作

> 文件名为兼容旧链接而保留。本文描述当前源码状态和仍需验证的事项，不再作为
> 从零开发的分阶段时间表，也不把历史计划中的未勾选项当作待办。

## 产品开发思路

**jidecards 不重点适配编辑器，更注重 Agent 改卡、制卡的能力，以取代手写制卡的主要工作。**

- 优先保障现有 Anki 牌组直接导入后的学习体验，包括离线数学、物理、化学公式和牌组自带媒体的显示。
- 内容创作重点投入自然语言驱动的 Agent 制卡与改卡，让用户通过描述意图、检查草稿和确认保存完成内容维护。
- 保留现有手动编辑与纠错入口，但不把复杂公式工具栏、所见即所得编辑器或手写排版作为近期重点。
- 渲染能力在学习页和卡片预览中共享，同样服务于导入内容和 Agent 生成内容；不因来源不同使用两套格式。
- 以上是开发优先级，不改变当前版本的 Agent 发布开关、草稿确认和写入安全边界。

数学与化学导入兼容的实现、边界和验收记录见 [离线公式渲染计划](math-chemistry-rendering.md)。

## 学习会话与自动同步边界

学习页的取卡、评分和撤销编排已提取到 `StudySessionController`，通过适配器复用既有后端服务；此次不修改 Anki Core、原生桥或同步协议。`AutoSyncScheduler` 合并成功学习写入产生的同步意图，首页负责前台、弹窗与导航安全检查。

每次答题先本地保存；连续学习时不启动自动集合同步，完成页或返回首页空闲后执行。正常自动同步不显示进度弹窗，错误提示和需要用户选择的全量冲突仍保留。完成页恢复学习须等待已开始的集合同步并重新取卡，媒体同步可以继续。此方案不承诺逐张即时上传或消除所有进入学习前的等待。

2026-09-18：完整 Node 回归与 Rust 双架构、ArkTS、签名 HAP 构建通过；设备操作由用户自行完成，本轮未安装或执行设备验收。

## 当前发布开关与限制

- 当前发布包的 AI 制卡、AI 改卡及设置入口默认关闭，可通过设置页的开发者调试功能统一解锁；
  实现没有删除，运行时开关由 `entry/src/main/ets/model/ReleaseFeatures.ets` 管理。
- Agent 页面当前固定使用 `searchMode: 'off'`。Provider 搜索协议仍在，但产品
  界面没有启用联网搜索。
- `docs/releases/3.0.0.md` 是未发布历史草案，不代表仓库或商店当前版本。
- `third_party/anki/` 是被忽略的本地依赖目录，不是仓库 submodule。构建者需要
  按 README 准备锁定提交。
- 自动化测试不能代替实体设备上的 UI、权限、前后台、媒体、同步和数据恢复验收。

## 发布前验证清单

每次发布至少记录以下证据；没有证据的项目应写“未验证”，不能沿用旧日期结果：

- `npm run doctor` 通过其当前覆盖的工具检查；另行确认
  本机签名和链接器的实际可用性；主机测试可使用已安装的 MSVC 或 bundled GNU 工具链。不得把 doctor 通过解释为
  完整构建已经通过。
- `npm test` 全部通过。
- `npm run build:app` 完成 Rust 双架构、ArkTS 类型检查和签名 HAP 构建。
- 只使用 `hdc install -r` 覆盖安装，确认不会删除用户 collection 与媒体。
- 至少在目标最低版本（当前 API 21）真机验证冷启动、学习、编辑、导入/导出、
  数据库检查和恢复路径。
- 在目标 API 23 的手机，以及计划支持的 tablet/2in1 上验证布局和关键交互。
- 对同步执行测试账号的无变化、普通双向、全量上传、全量下载、媒体中断恢复。
- 对会改变 collection 的高风险路径准备备份，并在失败时停止继续写入。
- 核对版本号、公告版本范围、README 和发布说明一致。

## 后续工作

当前仓库只维护可由代码或验证证据支持的后续项：

1. 为 API 21 最低兼容声明补齐可重复的真机回归记录；若要重新支持 API 12，必须
   先修改构建配置并完成所有高版本 API 的能力检查，不能只改文档。
2. 建立与官方 Anki 26.05 的固定集合差分测试，量化调度、搜索、导入导出和同步
   边界，再决定可对外使用的兼容措辞。
3. 在重新开放 Agent 入口前，完成实体手机、真实 Provider、取消/断网、普通写入
   和高风险写入回归；联网搜索应作为独立开关验收。
4. 对 tablet/2in1、无障碍、耗电和大集合压力测试保留可追溯的设备与版本信息。
