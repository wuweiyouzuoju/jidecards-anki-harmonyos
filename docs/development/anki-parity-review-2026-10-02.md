## 判断

26.05 会增加协议适配和兼容补丁，但不足以解释界面、代码组织及失败反馈的全部问题。此次多数功能已经复用现有会话、写入入口、公共弹层和样式；保留未知字段、卡片身份与调度记录所需的复杂度有实际价值。部分控件统一、预览流程与失败时草稿保护仍未完成，不能用“锁定旧版本”解释这些缺口。

`UPSTREAM.lock` 锁定 Anki 26.05 / e64c6b1。本机 AnkiDroid 源码及[官方 v2.25.0 依赖文件](https://github.com/ankidroid/Anki-Android/blob/v2.25.0/gradle/libs.versions.toml#L70)均使用 `0.1.68-anki26.05`。因此这是与参考客户端后端一致的选择，不能把 AnkiDroid 应用版本号和 Anki Core 版本号混为一谈。

桌面 Anki 已发布[26.09.3](https://github.com/ankitects/anki/releases/tag/26.09.3)，[26.09 变更](https://github.com/ankitects/anki/releases/tag/26.09)包含 FSRS 更新、编辑器与媒体修复；其中 Qt/Python 编辑器改动不会通过升级 Rust Core 自动进入鸿蒙界面。升级要独立核对协议、依赖、补丁和数据回归，不能只改锁定标签。

## 可定位的问题

### P2：偏好保存失败覆盖数字草稿

入口：[ReviewPreferencesSettings.ets](../../entry/src/main/ets/components/settings/ReviewPreferencesSettings.ets)。`save()` 在失败后回读真实偏好并调用 `apply(actual)`；`apply()` 同时覆盖三个数字输入，并清除 edited 标记。回读核对真实开关值有必要，但数字输入的用户草稿和持久化快照应分别保留。

复现：原日切为 4，输入 7，保存抛错，回读仍为 4；实际界面状态变回 4，`rolloverEdited=false`，同时显示失败。复现脚本执行现有组件方法，没有替换生产保存逻辑：`.local/anki-parity-audit-repro.mjs`。现有测试覆盖开关恢复及迟到结果，没有覆盖失败时数字草稿保留。

建议：维护最后确认值和输入草稿；失败回读只更新确认值，未被确认保存的输入继续保留，允许直接重试。须同时覆盖写入失败、已写入但回读失败，以及离页后结果失效。

### P2：图片遮罩编辑器控件样式遗漏

入口：[图片遮罩编辑器.ets](../../entry/src/main/ets/components/图片遮罩编辑器.ets)。完成多边形和添加/更新文字按钮使用平台默认 Button 外观；文字 TextInput 未使用 `FormInputStyle`。同屏其他工具已经显式设置高度、表面、字色、边框和按压态，因此这里存在源码层面的样式不统一。

工具区和画布采用 1:1.4 的剩余空间权重，缩放为 0.9/1.1 步进，旋转为固定 15°；没有画布缩放和直接变换手柄。这些是当前交互方案，26.05 的归一化坐标格式不要求如此设计。可先统一控件，再通过设备验收决定工具层级和精细编辑方式；本次没有把未经观察的设备外观判定为“难看”。

### P2：模板预览流程与可用面积需打磨

入口：[笔记类型编辑器.ets](../../entry/src/main/ets/components/settings/笔记类型编辑器.ets) 的 `previewTemplate()`、[NotetypeManagement.ts](../../entry/src/main/ets/model/NotetypeManagement.ts) 的 `previewFieldsUnchanged()`。字段结构或名称变化均阻止预览，来自当前未提交渲染接口读取已保存类型的限制。文案准确说明限制，但编辑→预览→确认的流程不完整。不能据此断定升级 Core 就能解除；应先核对新版接口，避免为预览偷偷保存真实类型。

入口：[NotetypeTemplatePreview.ets](../../entry/src/main/ets/components/settings/NotetypeTemplatePreview.ets)。Web 固定 300vp，其内容、提示、选择器及音频操作又处在弹层滚动区域。宽屏无法自动充分利用空间，窄屏/大字体/输入法状态可能需要多层滚动。源码可确认固定高度，最终设备效果仍未验证。

### P2：验证范围必须保持准确

[互通验证记录](core-interop-2026-10-02.md)和类型预览对话明确保留默认并行 FSRS 进程 `0xc0000409` 失败记录，并说明串行成功不证明问题修复。本次默认并行 FSRS 专项通过，因此当前不能宣布“并行必然失败”，也不能把偶发失败直接归因于 Anki 26.05。仍需定位其是否与并发构建、测试资源或原生运行有关。

七项任务均缺少本轮完整设备组合验收。Node 组件逻辑测试会剥离 ArkUI 渲染，HAP 成功证明编译和打包，浏览器像素测试证明桌面浏览器画布；三者都不能证明鸿蒙真实布局、软键盘、触摸与焦点表现。所有任务的最终交付都应继续保留这个边界。

### P3：成果汇总未完全同步

[SETTINGS_PARITY.md](../../entry/src/main/ets/components/settings/SETTINGS_PARITY.md) 原查重行仍写“只支持首字段、超过 1000 条拒绝”，与当前字段选择、批量读取及大集合 Core 测试矛盾。本次仅修正此处说明。历史验证数字保留日期和运行范围，不将不同时间的测试数量视为功能退化。

## 26.05 带来的合理复杂度

- [FsrsOptions.ts](../../entry/src/main/ets/model/FsrsOptions.ts) 将默认及 17/19/21 项参数交给 Core，按真实预设 ID 生成范围，避免名称歧义；这是兼容数据的适配，不应仅为减少代码删除。
- [anki-fsrs-workload-params.patch](../../tools/patches/anki-fsrs-workload-params.patch) 修复模拟基线对默认/旧参数索引越界；[新版模拟器](https://github.com/ankitects/anki/blob/26.09.3/rslib/src/scheduler/fsrs/simulator.rs) 已更换卡片参数表示。升级时应重做等价行为验证，再决定补丁移除或替换。
- Preferences 的未知 wire 字段保留、类型的原 ord、遮罩未修改片段原文和媒体缓存拥有者均用于防止数据损失。没有发现应把这些行为简化掉的依据。
- 本地查重 RPC 提供有界的只读批次，并复用 Core 的 HTML/媒体归一化；并不重新实现调度或改变锁定上游协议。

长文件和继承的模板化长注释会增加阅读成本，但不能仅按行数判定架构失败。本轮较有价值的边界是统一创建会话、类型写入会话、Core 偏好保存队列和草稿预览入口；后续应按状态拥有者及真实重复逻辑整理，避免只拆文件。
