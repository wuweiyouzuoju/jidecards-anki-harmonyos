# 开发任务契约

[返回任务索引](../../PROJECT_CONTEXT.md)

所有开发维护都要按风险落实本契约，局部文案修改可简短记录。执行结果可以写在交付报告；后续开发必需的入口、边界和长期决策必须进入受版本控制的领域文档或决策记录，不能只存在聊天上下文里。不要求为每次小改动新增计划文件。

## 开始前

- **目标**：要改变的用户行为或开发能力是什么？
- **范围**：会修改哪些目录、入口和边界？明确不包含什么。
- **责任**：每个受影响模块的唯一入口、状态拥有者和调用方向是什么？
- **不变量**：包名、签名、数据、协议、兼容性或 Agent-first 哪些约束不能破坏？
- **验证**：领域测试、仓库门禁、原生/HAP、设备验收分别运行什么命令？

## 完成时

- 实现、测试、文档和决策记录之间的入口可以互相定位。
- 新增复杂度有明确责任边界和直接验证路径。
- 实际执行的命令、未执行的范围和剩余风险已经记录。
- 后续编程 Agent 不需要依赖原作者记忆、临时文件或历史对话才能继续。

如果需求无法满足某一项，必须记录具体例外、原因和影响，不得用“以后补”代替交接信息。

## 交接模板

```text
目标与非目标：
本次修改路径与入口：
责任、状态所有者与不变量：
当前文档或决策路径（无变更则说明）：
实际验证命令、结果和对应工作树范围：
未验证范围、原因与剩余风险：
后续接手入口（无后续事项则说明）：
```

开始和交付前运行 `npm run impact` 检查范围。共享工作树中先保留其他任务修改，再区分本任务路径与全库验证结果；上次对话的测试结果不能冒充当前工作树的验证证据。
