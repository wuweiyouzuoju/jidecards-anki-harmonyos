# 开发任务契约

[返回任务索引](../../PROJECT_CONTEXT.md)

所有开发维护都要按风险落实本契约，局部文案修改可简短记录。执行结果可以写在交付报告；后续开发必需的入口、边界和长期决策必须进入受版本控制的领域文档或决策记录，不能只存在聊天上下文里。不要求为每次小改动新增计划文件。

## 开始前

- **目标**：要改变的用户行为或开发能力是什么？
- **范围**：会修改哪些目录、入口和边界？明确不包含什么。
- **同类覆盖**：按哪些语义、符号、资源和调用关系查找同类及替代实现？哪些共用责任入口，哪些差异需要保留？执行 [同类变更闭环](coding-agent.md#同类变更闭环)。
- **责任**：每个受影响模块的唯一入口、状态拥有者和调用方向是什么？
- **并行协作**：明确本任务范围、共享文件/接口负责人及依赖就绪条件；执行[多 Agent 协作](coding-agent.md#多-agent-协作)，不为通过验证代补其他任务。
- **不变量**：包名、签名、数据、协议、兼容性或 Agent-first 哪些约束不能破坏？
- **几何边界（UI 任务）**：对每个同类控件边界列出两侧所有 `padding`/`margin`/offset/inset 贡献，指定唯一间距所有者，并说明宽/窄及安全区状态下的最终距离；不得只比较单个属性值。
- **验证**：领域测试、仓库门禁、原生/HAP、设备验收分别运行什么命令？

## 完成时

- 实现、测试、文档和决策记录之间的入口可以互相定位。
- 新增复杂度有明确责任边界和直接验证路径。
- 实际执行的命令、未执行的范围和剩余风险已经记录。
- 后续编程 Agent 不需要依赖原作者记忆、临时文件或历史对话才能继续。
- 同类覆盖有查找和验证证据；说明已统一的入口、保留差异的理由，以及自动检查如何防止原问题重现。
- 用户可见设置、入口、菜单或操作的增删改已按[软件升级时的认知同步](coding-agent.md#软件升级时的认知同步)同步 JIDE；提供新版本目录/状态/能力的直接读取证据。未接通的当前值或操作保持明确不可用，不能只改界面或提示词后声称认知已同步。
- UI 几何任务已核对最终外缘距离，而不是仅核对局部样式字段；重复的边界贡献已由测试阻止。

如果需求无法满足某一项，必须记录具体例外、原因和影响，不得用“以后补”代替交接信息。

## 交接模板

```text
目标与非目标：
本次修改路径与入口：
责任、状态所有者与不变量：
同类查找范围、公共入口及保留差异：
当前文档或决策路径（无变更则说明）：
实际验证命令、结果和对应工作树范围：
未验证范围、原因与剩余风险：
后续接手入口（无后续事项则说明）：
```

开始时按本任务路径运行 `npm run impact`，交付前仅在范围或改动性质变化时更新计划。共享工作树先保留其他任务修改，检查本任务及受影响的公共依赖，一批改动稳定后集中完整验收。
相关输入未变时可以引用此前成功检查，注明范围；输入已变的旧结果不能作为当前验证证据。小改动使用简短交付说明，不为每次任务新增计划或交接文件；具体选择见[分级验证](verification.md#按变更路径选择验证)。
