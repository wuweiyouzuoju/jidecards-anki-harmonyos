# 首批新实现与接入契约

正式导出、真实使用方、构建与同步以[公共 HAR 接入](公共HAR接入.md)为准。以下是首轮重建的候选模块，**不是 jidecards 全部复用内容，也不是全部 HAR 公共 API**。完整已有实践及缺项见[复用全景](复用全景.md)与[跨产品接入规范](跨产品接入规范.md)。源码映射见 [provenance.json](../provenance.json)。

| 职责 | 实现 | 输入、结果和边界 |
| --- | --- | --- |
| 共用几何 | [UiTokens.ts](../src/core/UiTokens.ts) | 当前多个产品共用的页面留白、热区、表面和文字层级；不含闪卡/训练业务尺寸 |
| 动效和按压决策 | [Motion.ts](../src/core/Motion.ts) | `motionProfile(style)`、`pressVisual(style,state)`；克制/灵动显式选择，坏输入失败，无全局状态 |
| 点击可用性 | [Motion.ts](../src/core/Motion.ts) | `activateAction(enabled,busy,callback)`；禁用、忙碌或无动作不执行，正常操作立即执行，业务异常不被吞掉 |
| 主题语义 | [Theme.ts](../src/core/Theme.ts) | `themePalette(dark)` 返回独立对象；`resolveDarkMode(mode,systemDark)` 只计算，不存储或推测设备状态 |
| 安全区与键盘几何 | [SurfaceLayout.ts](../src/core/SurfaceLayout.ts) | `surfaceGeometry` 输入窗口尺寸、四边避让、键盘上缘；`surfaceBodyHeight` 统一预算，结果非负 |
| 日历日 | [CalendarDay.ts](../src/core/CalendarDay.ts) | `localDayKey` 明确使用本地日历；`addCalendarDays/calendarDayDistance` 不受夏令时影响；日期严格校验 |
| 触感事件与失败回退 | [Haptics.ts](../src/core/Haptics.ts) | `playHaptic(event,backend,enabled)`；预设失败才定时回退，最终失败上抛；偏好与触发时机由产品决定 |
| 原生按压适配 | [PressFeedback.ets](../src/harmony/PressFeedback.ets) | 平台 AttributeModifier 消费纯按压规则，不监听 onTouch、不延迟点击、不订阅 AppStorage |
| 普通动作按钮 | [ActionButton.ets](../src/harmony/ActionButton.ets) | `label/isEnabled/busy/isDark/motionStyle/onAction`；44vp 最小热区、原生按钮语义及完整读屏文案；不内置保存协议 |
| 内容状态 | [StateView.ets](../src/harmony/StateView.ets) | `title/description/loading` 和可选 `actionLabel/onAction`；没有真实动作或仍加载时不显示动作 |
| 弹窗表面 | [DialogSurface.ets](../src/harmony/DialogSurface.ets) | 实际 `viewport`、标题、内容插槽、`canClose/onRequestClose`；统一安全区及正文预算，无模糊、外投影或产品持久化 |
| 系统深浅色 | [SystemTheme.ets](../src/harmony/SystemTheme.ets) | `readSystemDarkMode()` 从设备资源读取；失败上抛，宿主保留已知值并负责生命周期和应用主题 |
| 系统触感 | [SystemHaptics.ets](../src/harmony/SystemHaptics.ets) | `SystemHapticBackend` 适配 vibrator；目标应用声明 VIBRATE 权限；调用方处理最终失败 |

## 组合方式

纯规则可单独使用。例如 UI 先按 `resolveDarkMode` 决定外观，再把 `isDark` 传给按钮和状态组件；不会因调用基础库隐式写入系统或产品偏好。

HarmonyOS 已发布入口优先使用公共 HAR。评估未导出的候选模块时，保持 `core/` 与 `harmony/` 的相对结构，并核对完整依赖；不复制旧积木。不需要触感时无需引入 SystemHaptics 或请求相关权限。

弹窗由窗口/页面宿主条件展示并拥有一次转场。宿主负责发布实际 `viewport`，处理系统返回并进入同一个 `onRequestClose` 守卫；回调只请求关闭，由产品决定草稿、忙碌和最终显隐。不要把遮罩关闭等同业务取消，也不要在内容层重复添加外壳内边距。当前组件是页面内表面，不替代原生窗口的生命周期管理。

文案从目标本地化资源解析后传入；新组件没有隐藏默认中文文案或产品资源键。危险确认、52vp 主训练操作、设置行、图标按钮和复杂原生弹窗保留产品现有实现，可参考下表继续适配，不能误称本次已经提供这些组件。

## 等级组件：独立源码入口

[Levels.ets](../Levels.ets)提供全系列共享账户等级的纯规则与卡片、详情、徽标、变化反馈组件，并导出独立的徽章定义、图案、原生展示与颁发准备；纪念/贡献不依赖等级状态。规则、共享存储和产品活动换算分别适配，UI 组合本目录既有组件。它使用独立入口，未加入当前 UI HAR；空间想象已接入本机等级、翻倍徽章及独立拥有记录。决定及 API 见[等级机制](等级机制上下文.md)，全系列翻倍勋章、纪念/特别贡献及色阶见[勋章设计与颁发](勋章设计与颁发.md)。

已获得单行陈列、详情和佩戴校验也由此入口提供：`SharedMedalStrip`、`SharedMedalDetails`、`resolveWornMedalId`。产品组合导航和操作按钮，保存用户选择；复用不意味着各应用数据已经同步。所有已发布 API 按各自入口接入，目录里尚未导出或仅作为候选的组件需按说明评估。
