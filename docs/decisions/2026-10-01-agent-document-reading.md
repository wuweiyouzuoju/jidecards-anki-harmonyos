# JIDE 按页资料读取与 OCR

## 决策

JIDE 使用通用 Responses 工具链读取资料，不绑定特定模型。原文件保存在会话沙箱，提交只提供文件 ID、格式和页数；PDF 按真实页读取，其他文本文档按 12000 字符分段。平台负责解析、渲染和 OCR，模型负责理解、制卡和保存可回查的页笔记。

## 原因与边界

旧 PDF 提取调用 API 23 才提供的 `getTextContent()`，低版本可能直接失败。改用 API 12 的 `getGraphicsObjects()` 文本对象，并保留单页 OCR 与渲染，最低兼容继续为 API 21。OCR 是 JIDE 可主动调用的系统能力；文字模型也能处理扫描件，不要求内置额外视觉模型。

视觉请求由当前模型能力控制，自定义服务需显式开启视觉支持。原文、OCR 结果、模型笔记分开存储；页面图片只进入当前请求，不进入历史 JSON。卡片可引用实际读取过的文件页，创建仍经既有可编辑草稿和确认入口。页数不表示读取覆盖，复杂排版、公式和识别准确率需要用户验收。

## 验证入口

入口与责任见 [Agent 领域文档](../development/agent.md#文件资料与按页制卡)。`npm test -- agent` 验证真实 Store、Registry、Runner 与 Session 的连接，包括缺少 API 23 方法的平台支架；`npm run verify` 完成全部主机检查及签名 HAP。独立 [设备测试工具](../../tools/test-agent-documents-device.mjs) 使用合成 PDF 与图片，可检查真实 PDF/OCR SDK，不使用模型密钥或卡库。

本次按用户要求只覆盖安装平板，具体操作和 PDF/OCR 效果由用户验收；不将主机支架或安装成功记录为真机识别通过。
