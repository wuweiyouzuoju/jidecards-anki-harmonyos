# 软件开发同时维护 JIDE 认知

日期：2026-10-04

## 决策

用户可见设置、入口、菜单和操作的增删改，同时维护 JIDE 认知，作为普通开发任务的完成条件。编程 Agent 默认负责接入与验证，用户无需另外提醒。当前规范唯一入口为[软件升级时的认知同步](../development/coding-agent.md#软件升级时的认知同步)，根开发约定、界面局部规则和任务契约只引用它。

运行时沿用现有共同声明、真实工具与状态观察。认识结构、读取当前值和执行操作分别声明能力；新增 UI 不自动授予修改权限。后续新增设置优先让 UI 和 JIDE 消费同一来源，不维护另一份软件功能清单或要求模型记忆每次升级。

## 原因与边界

当前版本能重新生成已登记的认知，但运行时无法可靠判断任意手写 UI 的业务含义和真实权限。仅说明“认知会刷新”不足以保证后续开发没有遗漏，因此把接入责任放在开发完成条件，并对可识别的登记关系增加自动检查。

不增加通用源码扫描、视觉探索或自动点击框架。测试扫描整个设置组件树，验证静态共享标签、资源和目录关系；未使用共同入口的手写控件或动态表达式仍需开发 Agent 查全并接入，检查不能替代实际行为验证。

## 影响与验证

`SettingsStructure` / `SettingsNavigation`、`AppInterface` 和原工具边界保持现有所有权。`npm run impact` 将设置组件和共同认知契约变更导向 Agent 领域回归；现有完整 Node 验证自动发现相关测试。

`ai-agent-app-structure.test.mjs` 执行共享标签与目录的新增、改名、显隐和删除行为，并扫描新增设置组件；`ai-agent-app-settings.test.mjs` 验证真实 Registry 的读取边界；`change-impact.test.mjs` 验证相关路径自动安排认知检查，`documentation-contract.test.mjs` 验证规范可从开发入口找到。生产界面、读取器或工具改动仍按原分级规则补领域/平台/设备验证。
