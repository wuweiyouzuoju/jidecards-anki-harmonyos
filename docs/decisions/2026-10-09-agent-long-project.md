# JIDE 长期记忆与长任务恢复

## 选择与原因

在历史页顶栏的“＋”左侧增加记忆入口。手动管理与 AI 提案复用 `AgentWorkspaceStore` 和旧快照冲突校验，避免形成两套偏好。`AgentMemoryPanel` 拥有编辑和退出状态，`AgentMemoryManager` 拥有读取代次和手动提交；已接受的提交独立于界面完成，保存失败保留草稿。

复杂任务的目标、步骤、决策和接续笔记归 `AgentScope.taskPlan`，通过版本化 `get_task_plan` / `update_task_plan` 工具读写。计划随会话检查点保存，新会话清除；长期偏好与任务进度分别保存，因为适用范围和生命周期不同。计划没有卡库写入权限，也不能作为执行成功证据。

Runner 在模型请求前和工具完成后发布检查点，Session 保存当前计划、协议和范围。持久化失败停止当前执行；批内尚未完成的工具只在检查点副本中标记为中断。恢复不会重放历史副作用，实际副作用与检查点之间的崩溃仍需要读取真实状态核实。

模型预算由 `AgentExecutionBudget` 选择，预检和发送使用同一完整序列化计量。内置 DeepSeek 提高预算，其他兼容接口保留原值；字符预算没有替代模型的 token 上限。每次请求只装入有界的完整相关记忆，剩余条目按需搜索，配合已有上下文整理减少重复资料。运行额度与请求额度的事实来源和详情见[当前领域说明](../development/agent.md#长期记忆管理与长任务2026-10-09)。

## 影响与验证

涉及记忆 UI、AppInterface 实际观察、辅助工具目录、Session/Runner 接续、Provider 请求及历史快照。沿用既有牌组范围、提案确认、卡库写入执行器和原生接口。

`npm test -- agent` 覆盖超旧额度的长工具链、批内中断、计划恢复、磁盘失败、手动与 AI 冲突、组件取消退出及大上下文；架构、资源、ArkTS 字段和文档契约专项检查负责跨层约束。`npm run build:app -- -SkipRust` 验证 ArkTS 与增量签名 HAP。本轮未改原生代码，不重新编译 Core；未进行设备布局验收或付费模型评测。

2026-10-09 验证结果：上述 Agent 套件和专项检查通过；最终增量签名构建成功，警告门禁 `unexpected=0`。这是当前改动的主机验证记录，不是整库 clean 验证或设备验收结论。
