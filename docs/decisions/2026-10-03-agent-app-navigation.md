# JIDE 当前软件认知与自动导航

## 选择

页面名称和受控导航动作放在 `model/navigation/AppNavigation.ts`，由真实 `HomeDestinations` 与 JIDE 共用。结构工具按当前共同声明和实际工具生成目录、详情覆盖及能力指纹，每次 Provider 请求加入当前目录，避免恢复旧会话后沿用过期认知。

JIDE 的导航通过独立 `navigation` 工具类别接受语义请求，由当前页的 `AgentAppNavigationSession` 排队，成功回复保存历史后再交给首页 Navigation 宿主。后端不 import 页面、不持有页面栈、不获得卡库写入权限。

## 原因

立即从工具调用跳转可能销毁或遮住 JIDE，使尚未完成的模型接续、错误展示和历史保存失效。排队把模型工具结果与真正进入页面分开，明确返回 `queued`，失败/取消不遗留自动跳转。沿用真实学习、浏览和设置入口，避免另写学习队列或绕开确认执行器。

纯会话拥有代次、当前用户意图和队列；首页仅拥有导航效果。接受/执行两次检查牌组与占用，旧轮次不能消费新轮次请求。已存在学习会话时拒绝再打开第二个学习页。

## 范围与验证

首批接通开始牌组学习、浏览搜索、设置分组、统计、提醒、添加笔记。共同声明的修改自动进入当前认知；未登记的弹层/按钮不自动获得详情或动作，评分、删除、同步与保存继续沿用各自领域边界。

后续扩展接通返回首页、打开指定笔记编辑和卡片预览。动作表同时拥有必需/可选参数，校验、模型参数说明与结构工具从同一声明生成；新增动作的真实宿主执行必须通过逐声明回归，避免目录已出现而页面未接通。目标校验统一为只读 Scope + 真实对象读取，编辑只传笔记 ID，预览通过浏览页初始搜索打开原组件。首页清栈拒绝丢弃下层编辑/新增表单，JIDE 新输入的未发送消息也阻止跳转。

`npm test -- agent` / `npm test -- home` 反馈实际会话、Registry、Runner 接续、导航与参数映射；`npm run verify` 验证全库、原生门禁和 clean 签名 HAP。主机验证不代表真实模型或设备 Navigation 交互已验收。

本次导航新增行为回归、真实 Runner 接续和首页领域检查通过；`npm run build:app -- -SkipRust -Clean` 完成签名 HAP，警告门禁新增为零。`CARGO_BUILD_JOBS=1` 的 `build-native.ps1 -Target host-test` 与 RPC 基线检查通过。本次没有原生源码修改。共享工作树的整库验证曾在原生阶段失败，降低并发后原生检查通过；后续完整 Node 检查遇到同步进行的公共菜单/边框改动对应的 UI 契约失败，不能据局部通过声称整库 `verify` 已通过。未安装或操作设备，未向真实提供商发送验收请求。

后续扩展验收：导航、真实 Runner、页面认知、参数映射、架构/资源/文档共130项专项通过；`npm test -- home` 的322项与 `npm test -- browser` 的419项通过。最终 `npm run build:app -- -SkipRust` 增量签名 HAP 通过，新增警告0；复用已构建的双架构 Core，本轮未改原生源码。`npm test -- agent` 的512项中510项通过，另两项失败分别来自 `ai-agent-conversational-ui-contract` 的既有边框源码断言和 `ai-agent-math` 的组件源码提取；本轮未修改这些组件/测试，不以专项通过声称 Agent 全套通过。没有重复全库/原生验收，也未调用真实模型或安装设备。
