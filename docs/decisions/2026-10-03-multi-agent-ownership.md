# 多 Agent 的任务归属与失败处理

状态：已采纳。适用于负责修改仓库的编程 Agent。

原因：并行任务的未完成接口使共享编译失败时，其他 Agent 代补最小实现会覆盖真实设计，并使通过结果失去可信度。

决策：任务边界、共享文件写入负责人和依赖就绪条件明确后协作；失败先归因，其他任务由负责人处理或明确交接。禁止以占位、假成功、回滚他人工作或弱化检查换取通过。日常各自局部验证，稳定后由指定集成人联合验收。

唯一执行细则与开源依据见[多 Agent 协作](../development/coding-agent.md#多-agent-协作)。不增加强制任务登记系统、独立分支或每次全量构建；冲突确需隔离时使用 worktree。

验证：文档契约及差异检查；实际任务通过 diff、失败证据和交接范围核对执行，文档检查不证明运行中的 Agent 已遵守规范。
