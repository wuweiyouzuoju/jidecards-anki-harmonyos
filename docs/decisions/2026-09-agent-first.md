# Agent-first 开发优先级

## 决策

编程 Agent-first 是 jidecards 的最高开发优先级。所有新功能、修复、重构、测试和文档变更都必须优先提升编程 Agent 的理解、修改、验证和持续交付能力。应用内 Agent 是产品运行时能力，按产品需求维护，不得成为编程 Agent 治理规则中的第二个优先级。

应用内 Agent 是产品运行时能力，编程 Agent 是负责修改仓库的开发者工具。两者在文档、任务入口、测试和实现边界中必须明确区分。

## 影响

- 根 `AGENTS.md` 和 `.agents/` 是编程 Agent 的约束来源。
- 历史计划、`.trae/` 和归档材料不得包含当前执行指令。
- 新能力必须有清晰入口、稳定边界、测试入口和当前文档。
- 与普通产品目标冲突时，优先保持 Agent-first；用户明确指定其他目标时，任务报告需说明例外及影响。

## 验证与执行边界

目录规则按路径主动读取，`npm run impact` 只读生成最低验证计划，`npm run verify -- repo` 自动运行路径工具回归及文档契约。路径分类不等于完整依赖分析，也不自动证明任务完成；运行时、构建和设备验证按实际影响执行并记录结果。

采用只读计划是为了让后续编程 Agent 从同一入口获取可复现的范围，同时不擅自执行签名、设备安装或发布。新增路径规则需要测试覆盖，长期边界必须落在当前文档中，不依赖历史对话。
