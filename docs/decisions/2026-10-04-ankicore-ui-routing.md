## 判断口径

- **较复杂 UI**：需要组合条件、列表排列、源码配置、参数比较或新的结果工作台。操作通过 JIDE 读取当前值、生成提案、展示差异并复用已有确认卡执行；不新建高级设置页、图表工作台或通用规则编辑器。
- **极其简单 UI**：现有页面增加输入框、开关、按钮、少量结果文字或跳转；也包含完全不增加 UI、只补底层接入的事项。下表说明最小界面范围，实际协议、存储和运行时开发仍可能复杂。
- 按**本次缺少环节所需的新增 UI**判断。已有复杂页面的工具接入不要求重做页面；运行时修复也不因实现困难而归成复杂 UI。
- 之前明确只通过 JIDE 提供的高级能力继续维持该入口。归入简单类意味着能以很小的 UI 成本完成，不表示本次要求新增手动入口。

原盘点的 22 个 G 编号全部覆盖：G09/G13/G14/G15 归复杂类，另外 17 组归简单或无需新增 UI，G21 拆为复杂配置与简单维护。原报告的 JIDE 专属差距和平台后续项也在各类后列出。事实、源码入口和验收依据以原盘点为准，此处只记录入口选择。

## 实施约束与顺序

1. 先补无需新增 UI 的实际效果：G02 字段属性、G03 批量撤销、G22 音频顺序、G16 导入默认值；G01/G12 单独推进底层方案。
2. 简单管理入口复用原组件和领域服务，优先 G04/G05/G06/G17 及 G21 的清空/重建；增加入口时按现有共同声明同步 JIDE 的读取、操作及能力边界。
3. 复杂配置接 JIDE：G14/G15/G21 配置优先，之后 G09/G13 及牌组选项等工具覆盖。写入沿用 Scope、冻结提案、确认和提交前重查，读取/计算返回真实结果；JIDE 新工具不等于功能已接入。

本决策补充原接入盘点的入口选择，保持已有 UI 和此前 JIDE 专用能力的约定。它没有改变锁定 Core、集合写入和模型运行时权限边界，也不要求把直接学习、编辑或画布交互全部改成对话。
