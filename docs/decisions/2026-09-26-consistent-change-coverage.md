# 同类变更的发现、复用与验证

状态：已采纳。适用于负责维护 jidecards 的编程 Agent。

## 问题

同一类界面问题被多次反馈后仍可能在其他页面重现。只修改截图指向的位置、只写规范，或只搜索已使用公共组件的调用方，都不能发现仍在散写的副本。知识留在聊天中，还会让后续 Agent 重新踩同一个坑。

## 决策

将“主动查全同类 → 明确唯一责任入口 → 公共实现承载规则 → 自动检查防遗漏 → 索引和验收提供证据”作为项目级工作方式，不局限于 UI。执行细则唯一维护在 [编程 Agent：同类变更闭环](../development/coding-agent.md#同类变更闭环)，根指引和工作流链接该入口。

文档说明责任、差异及原因；代码负责真正的共用行为；测试负责发现可检测的回退。三者相互指向，不能用其中一个代替另外两个。公共模块附近的注释只记录容易误改的不变量，索引用实现符号和查找方法定位使用位置，不另维护重复的事实清单。

## 取舍与边界

- 不采用仅加文档提醒的做法：它仍依赖每位 Agent 记住并逐处执行。
- 不采用每次手工复制修复到所有页面的做法：下一次新增页面仍可分叉。
- 不要求形式相似的代码全部合并：先确认语义、状态所有权和变化原因。合理差异保留并解释，禁止为统一而建立万能模块。
- 不把查全扩展为无关产品改造。修改范围仍由用户目标限定，设备视觉验证也不能由源码扫描替代。

## 维护与验收

发现同类漏改时，除功能修复外，检查缺口位于发现方法、公共责任边界还是回归检查，并修补对应入口。新增同类实现应通过公共模块接入，不能绕过已有约束。

[任务契约](../development/task-contract.md) 要求交付同类覆盖证据；[验证约定](../../.agents/rules/testing.md) 区分行为测试、静态约束和设备验收。当前文档链接与规则由 `npm run verify -- repo` 验证，功能实现另按受影响领域执行验证。本记录补充既有 [Agent-first 边界决策](2026-09-26-agent-first-boundaries.md)，不改变其状态所有权和分层原则。
