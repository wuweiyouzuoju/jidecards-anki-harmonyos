# 工程约定

主要依据：闪卡开发约定、任务契约、职责边界、分级验证。魔方与空间训练已经采用其中的职责治理方式，具体入口见[复用目录](复用目录.md)。

## 定位与职责

1. 先读目标项目的当前入口和适用规则，检查工作树；沿本次行为查入口、状态所有者、生产方、消费方与相关测试，保留他人未完成改动。
2. 按语义查全同类实现与旧写法，说明保留差异的理由。修复公共责任入口，再核对调用方；页面局部覆盖不能代替公共修复。
3. 通用依赖方向为 UI → 应用编排 → 纯业务规则/服务接口 → 平台或存储适配。纯规则不读取 Kit、页面或可变 UI 状态；平台适配不决定业务正确性。
4. 每个可变状态有明确所有者；派生展示由事实计算。不要同时维护两套等级、计数、完成标记或偏好真相。
5. 按职责与变化原因拆分，实际多个使用方形成稳定契约后再抽取。文件行数、删除比例和未来可能使用不构成抽象理由。
6. 修改契约同时核对调用方、数据迁移、旧格式和失败路径；结构重组保留行为并提供对应证据。

## 异步、持久化与恢复

- 已接受的写入由业务/存储拥有，不随页面隐藏或销毁而被当作取消。关闭展示、请求取消与业务实际结束分别建模。
- 读取、生成和资源回调校验请求身份或代次；旧结果不能覆盖新选择、重新打开旧页面或消费新会话的资源。
- 同一业务完成使用稳定身份去重；重试不能重复记成绩、经验或奖励。快照与完成记录存在关联时，以事务或等价的一致性边界处理。
- 设置修改经公共入口串行保存、校验原值、回读确认后发布；区分保存未确认、已保存但应用失败。读取失败、损坏值和没有数据分别呈现。
- 进程重启、后台暂停和 UI 重新显示不依赖旧内存时钟或旧句柄；恢复规则由会话和数据格式显式定义。
- 资源拥有者负责释放，包含原生句柄、图像、监听器和计时器；迟到回调不能复活已释放资源。

可参照：LocalPreferenceWrite、空间训练数据契约、魔方运行时。这些是模式与真实入口，不能把业务服务整包搬入新产品。

## 用户能力与应用内助手

有应用内助手的产品，设置、入口、菜单和能力增删改时同步它的真实软件认知：名称、位置、显隐条件、状态与可执行操作。优先共用 UI 声明和状态拥有者，操作仍走原领域入口；没有接通的能力明确不可用。

这项规则来自闪卡的 JIDE；没有助手的产品无需因此增加助手、认知系统或提案框架。具体接入见闪卡认知同步约定。

## 验证与交付

| 改动 | 所需证据 |
| --- | --- |
| 文档、文案、图标、颜色和简单留白 | 链接/资源/引用检查；视觉变化核对最终外观 |
| 局部行为与数据规则 | 执行真实模型/编排的相关回归，包含失败与边界 |
| 新组件、类型或平台 API | 相关行为检查，加目标工程增量编译/HAP |
| 原生、协议、持久化格式 | 对应边界测试、兼容或迁移验证与编译 |
| 集成、依赖/SDK 升级、发布 | 所属项目完整验证与必要设备验收 |

这是系列选择原则；目标项目明确的更严格完成要求仍适用。使用它已有的 impact/test/build 入口，不为统一命令名另建框架。impact 只列计划，测试列表只列文件，构建成功只证明构建；均不能替代行为、布局、GPU、触摸或设备证据。

优先运行受影响的最少必要检查。相关输入未变化的证据可注明范围后复用；变化或失败后补相应检查。不要用源码文字存在替代真实行为，也不要为通过检查删除有意义的断言。

交付说明保留：目标和修改入口、状态及契约、同类覆盖与合理差异、实际命令和结果、未验证范围及下一步。关键原因写回所属项目当前文档；历史计划只作追溯。

## 平台与资产边界

- 新标识符使用英文，注释简明记录中文意图、不变量与原因；既有局部命名按项目规则维护。
- ArkTS/HarmonyOS 实现以目标项目 SDK、实际声明和适用技能为准；不能从某个组件最低版本推导整套能力均可使用。
- 修改保持既有身份、签名、数据与已定技术路线。已有设备覆盖安装，安装方式遵守目标项目规定；不得用卸载清数据完成验证。
- 复用保留实际来源、内容哈希、许可证标识与改造范围；本机签名、发行密钥及私有材料不进入通用资产或导出。
- Anki 调度及协议、魔方求解/GL、空间几何判题等归各自产品；跨产品采用需要单独的职责和兼容性判断。
