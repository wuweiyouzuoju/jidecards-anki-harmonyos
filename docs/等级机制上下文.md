## 责任与适配边界

全系列共享意味着各软件必须使用同一账户身份、状态来源、等级标尺及规则版本。各软件分别适配有效活动、完成身份、贡献换算和维护依据；不能各自维护一份互不联通的“共享等级”。

- **共同实现**：[纯规则与契约](../src/core/Levels.ts)拥有贡献累加、版本与边界校验、风险缓冲、回退、最高等级和成就派生。[UI](../src/harmony/Levels.ets)只接受数据、主题、文案和回调。
- **系列共享宿主**：实现 `SharedLevelStore`，负责账户身份、持久化事务、可信时间、活动授权/校验和跨应用同步。共同等级标尺、缓冲时长、成就门槛由该宿主按一个版本发布；公共库不写死数值。
- **产品适配**：从已保存成功的业务事实生成稳定活动 ID，按系列当前版本换算贡献量；明确本产品的维护依据。产品适配入口和换算说明写入其现有领域文档。
- **界面宿主**：拥有页面/弹窗显隐、安全区、主题、文案本地化、反馈确认与失败重试；根据所选形态组合组件。

当前公共 UI HAR 的导出及现有产品接入由原公共基础任务维护。等级使用独立源码入口，没有自动混入现有产品的 HAR。复制源码时，可用已有 `sourceClosure` 从 `Levels.ets` 解析完整依赖；保留目录结构及 AGPL-3.0-or-later 标识。只需要模型时从 `src/core/Levels.ts` 接入，无须带 UI。

纪念/特别贡献徽章的定义、独立颁发准备与图案归 `src/core/Medals.ts`，不放入等级快照。它们由同一 `Levels.ets` 源码入口导出，当前色阶、资格状态及原生图案组件见[勋章设计与颁发](勋章设计与颁发.md)。

## 模型与 API

| 入口 | 用途与约束 |
| --- | --- |
| `LevelRules` | 一个共同 `version`、纯函数标尺 `scale.resolve(points)`、正数缓冲时长 `graceMs`、成就门槛 `milestones` |
| `LevelRules.milestoneSource` | 可选动态门槛来源；`DoublingLevelMilestones` 按公式生成系列翻倍勋章，不依赖有限列表 |
| `UniformLevelScale(step)` | 可运行的等距标尺；step 必须显式提供。可以替换为同接口的增长曲线，不使用有限等级表 |
| `SharedLevelAccount(store,rules)` | 共享领域入口，不访问平台 Kit、产品数据库或全局 UI 状态 |
| `contribute(accountId,activity)` | `productId + activity.id` 去重；正整数贡献，成功保存后返回状态；跨多级仅产生一条变化反馈 |
| `proposeRisk(accountId,risk)` | 保存预警及说明，暂不扣减；同账户一次只处理一个活动预警，避免多个产品叠加惩罚 |
| `markWarningSeen(accountId,action)` | 实际展示预警后保存已读时间，从此开始缓冲。重复展示不重置期限 |
| `settleRisk(accountId,assessment)` | `assessment` 含预警 ID、可信时间、评定依据对应的 `expectedRevision`、是否仍处风险 `isStillAtRisk`。未读或未到期不扣减；恢复条件则解除预警；旧快照的评定拒绝并要求重新评定 |
| `acknowledgeNotice(accountId,action)` | 确认或跳过指定反馈；不会撤销进度、成就或等级 |
| `summarizeLevel(state,rules)` | 得到当前/最高等级、本级进度和下级所需量；供宿主格式化文案 |
| `createLevelState(...)` | 创建初始状态或承接经过明确换算的可靠旧数据；正式导入由共享宿主一次性事务保存 |
| `validateLevelState(...)` | 坏值或旧 schema/ruleVersion 明确失败，保留原数据；不清空重建、不自动猜测迁移 |

`LevelState.points` 是当前评定量，允许回退；`lifetimePoints` 是确认获得的累计贡献，不随回退减少。`highestLevel` 和已获成就保留。`revision` 是整个账户的状态版本，反馈确认也可能使它增长，评定方应按最新快照重新判断。

标尺契约：从 0 点的 Lv.1 开始，随评定量单调递增，返回包含输入点数的 `[start,next)` 区间；每个等级均有下一阈值。数值采用非负安全整数，超出 JS 精确范围时明确失败；“无上限”指没有业务满级，不承诺无限数值精度。自定义标尺必须由共享宿主固定版本并保持纯函数。

## 保存、重试和恢复

`SharedLevelStore.transact` 是必须真实实现的边界，而非普通的“读后写”：

1. 按账户串行或通过数据库事务/CAS 重试执行 update。状态与去重回执在同一事务提交。
2. 相同 operationId 和 fingerprint 的重试不再执行 update，返回该账户最新状态。相同 ID 但贡献或业务内容不同要报冲突，不能静默覆盖。
3. `changed=false` 的延后评定不写完成回执，否则缓冲到期后会永远无法结算。活动、风险、已读、结算、反馈确认的身份分别命名。
4. 使用共享宿主的处理时间，不用设备随意修改的时钟或离线活动的旧时间作为评定时钟。小于已保存 `updatedAt` 的新评定被拒绝。
5. 结算前根据最新账户重新检查维护条件，并传入该快照 revision。期间发生贡献或其他更新则要求重评，不能拿旧判断扣减新状态。
6. 降级扣减当前余额，不回写预警创建时的旧余额；缓冲期间新贡献保留。余额最低为 0，历史最高和已获成就不减。
7. `warning`、待展示 `notices` 与回执一起持久化。重启继续原缓冲，恢复不重复积分或扣减。提示被跳过不影响业务完成。

产品业务完成与共享提交之间使用其现有可靠队列/outbox 或可重放的已保存事实，以稳定身份重试。网络断开时保留待同步事实与最后确认状态；没有共享宿主时应呈现未接入/未同步，不能创建另一份独立等级来冒充系列共享。

[DemoLevelDatabase / DemoSharedLevelStore](../examples/LevelDemoStore.ts)提供单进程串行事务与快照恢复样例，测试直接执行同一个实现。它只保存在内存，JSON 快照是回归夹具，不是生产跨应用同步方案。真实接入需替换存储宿主并验证其事务、进程终止和网络重试。

## UI 契约与已有组件

UI 遵循[界面与交互](界面与交互.md)，组合 `UiTokens`、主题、`ActionButton`、`StateView` 和 `DialogSurface`，继承既有热区、表面、安全区及按压语义。具体外观仍需设备验收。

| 组件 | 输入与职责 |
| --- | --- |
| `SharedLevelBadge` | `model / isDark`；紧凑静态徽标，完整文字自然布局 |
| `SharedLevelCard` | `model / isDark / motionStyle`，可选 `detailsLabel / onOpenDetails`；等级、称号、进度和维护预警 |
| `SharedLevelDetails` | 同一 model；展示历史最高及已获成就。它是正文，不另建滚动或弹窗宿主 |
| `SharedLevelFeedback` | model、notice kind、标题、说明、关闭文案、viewport、主题、busy、reduceMotion、确认回调；晋级弹层可随时跳过，其余为轻提示 |

以上等级组件可选接收 `medalSource / medalLabel / medalOrdinal`，由宿主提供已获得图片与汉字枚序。独立 `SharedMedalTile` 显示图案、名称、条件、状态与时间；`SharedMedalIcon` 处理 Harmony 不支持 SVG 文字的适配，使用公共 `medalNumeral` 和 `medalInk`。完整定义见[徽章规则](勋章设计与颁发.md)。

`LevelViewData` 是已格式化的展示数据；称号、徽章名称、进度说明和本地化由宿主传入，公共 UI 没有产品名分支或隐藏资源键。进度来自 `summarizeLevel`，不在控件中重新计分。

反馈使用对应 `notice.toLevel` 格式化当次等级，不能把更晚的当前等级当作旧通知的晋级结果。详情使用最新账户状态。只有预警真正展示后才调用 `markWarningSeen`；确认/关闭/系统返回走同一个宿主处理，保存失败保留提示并允许重试。`reduceMotion=true` 跳过晋级动效，不影响业务或关闭操作。

[可操作原生示例](../examples/LevelShowcase.ets)包含两个产品贡献入口、三种展示、深浅色切换、预警展示、缓冲结算和恢复维护条件；使用真实等级 API 和示例事务。示例中的 100 点一级、5 秒缓冲、贡献量和成就门槛均只为演示，不是正式规则。

## 接手与产品迁移

后续 agent 先读本页，再读目标产品 AGENTS 和现有领域说明。按以下入口完成适配，不再重新问已确认的体验选择：

1. 明确系列账户及共享宿主，接通 `SharedLevelStore`；所有产品消费同一规则版本。
2. 查全真实完成入口及重试/恢复路径，确定唯一业务事实、稳定身份和贡献换算。参数仅在共享宿主或目标产品所属规则位置维护，本页只保存共同契约与引用。
3. 按产品实际情况实现维护评定；在共享账户层协调多个产品的维护条件，避免一产品闲置却惩罚整个系列的正常使用。规则文档写明原因、来源、周期、补救方式和降幅。
4. 可靠旧记录通过固定导入身份一次性转换；原数据与导入水位保留，不能把各产品旧等级直接相加。schema 或规则变化明确迁移当前量、累计量、最高等级、成就、预警、通知与去重记录，并保留回滚依据。
5. 接入实际 UI、失败状态及助手认知（仅有应用内助手的产品）。用真实产品验证事务、网络、退出恢复和最终外观。

现有参考入口：空间完成及学习等级、魔方训练、魔方历史、舒尔特训练、闪卡学习。它们的旧规则各自保留，不能当作新系列贡献换算的默认批准。
