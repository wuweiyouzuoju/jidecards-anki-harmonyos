# 文件导入与导出

公共入口为 `Index.ets` 的 `selectTransferFile`、`saveTransferFile`、`copyTransferFile`、`transferFileName`、`transferExportName` 和 `FileTransferObserver`。实现只依赖 AbilityKit / CoreFileKit；纯文件名规则位于 `src/core/FileTransfer.ts`。

来源为当前记得闪卡 `DataTransferFiles.ts` 的异步 64 KiB 描述符复制、`数据迁移服务.ts` 的系统保存流程、`文件导入助手.ets` 的单文件过滤选择与 `ImportFile.ts` 的 URI 文件名处理。提炼时保留短读短写、取消上抛及描述符释放；增加复制前大小限制、提前 EOF 拒绝、成功前 fsync、导出文件名清理。来源快照及 SHA256 见 `provenance.json` 的 `file-transfer`。闪卡当前调用链保持原状，尚未回接本 API。

选择器取消返回 null，平台错误传播给产品。保存返回目标 URI 之前必须完成复制和刷盘；失败可能在用户选择的位置留下部分文件，不会将其报告为成功。基础库不删除用户原文件或目标文件。临时目录、资源包的 finally 释放、确认、占用、恢复、原子提交及错误文案均由产品拥有。FileTransferObserver 的 check 可抛出产品取消异常，progress 只报告实际复制字节，观察者异常同样终止复制并释放描述符。

建筑世界及记忆宫殿通过现有专用 vendor 版本同步入口消费本能力：`jide-world-core/platform/PalaceDataController` 调用选择与保存，`PalacePackageStore` 调用异步限额复制。ZIP 路径安全检查、格式版本、SHA256、资源依赖闭包和独立副本身份仍归建筑模块；不把 APKG / COLPKG、Anki Core、CSV、集合恢复协议移入基础库，也不宣称这些格式可由建筑世界导入。

验证：`node --test tests/file-transfer.test.mjs` 执行实际生产适配器，替换平台边界，覆盖短读写、提前 EOF、超限、取消、读写及刷盘失败和保存返回顺序。`npm test`、`npm run check`、`npm run build:harmony` 为基础库检查；建筑工程执行 `npm run build:both`。真实文档提供方与设备布局另行验收。
