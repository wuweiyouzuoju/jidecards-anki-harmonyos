# 新产品接入

这是接入时填写的简短模板，内容进入目标产品已有的当前文档；无须复制整套规范或另建规则框架。

## 先确定

```text
产品、目标用户与主任务：
代码目录与当前入口：
平台、应用身份和已接受的技术路线：
首次接入的复用项及来源：
需要保留的产品差异：
本轮完成标准与验证入口：
```

从目标的真实页面和调用链选资产，不一次性引入全部闪卡服务。新平台可复用纯规则、数据格式、样例和行为契约，界面及存储使用平台适配；不得假定 ArkTS 文件能直接用于其他平台。

## 接入顺序

1. 读取[工程约定](工程约定.md)和目标项目当前规则，检查已有同类实现。
2. 先查[复用全景](复用全景.md)与[跨产品接入规范](跨产品接入规范.md)，确认完整行为及真实使用方。已导出能力使用[公共 HAR](公共HAR接入.md)，其他能力评估[候选模块](复用目录.md)或原产品当前实现。核对数据、资源、回调、状态和失败语义；不能因首批简化模块已存在便替代成熟能力。
3. 按[界面与交互](界面与交互.md)集中建立目标 token 和语义映射，先贯通一个真实流程，再推广同类入口。
4. 记录来源和改造；同步真实调用方、相关测试以及目标当前文档。
5. 在新基础运行 `npm test`、`npm run check`；迁入产品后继续运行该产品受影响的行为/构建检查，有 UI/设备行为则留下对应证据及未验证范围。已有数据先验证兼容，不能通过重置绕过。

## 差异记录模板

| 项目 | 当前选择 | 原因与证据入口 |
| --- | --- | --- |
| 页面密度与字体层级 | 待填 | 目标平台与内容 |
| 颜色/主题和图标 | 待填 | 语义映射与明暗资源 |
| 动效默认 | 待填 | 产品选择；克制/灵动的来源 |
| 弹层与返回策略 | 待填 | 窗口、键盘、草稿与忙碌守卫 |
| 记录、等级和奖励 | 待填 | 业务含义、数据来源与迁移；不能直接套别的产品阈值 |

## 完成时留下

```text
实现与状态所有者：
已复用资产及来源记录：
同类覆盖与差异：
实际检查命令、结果和对应输入：
未验证范围及下一步：
```

后续产品只需要引用本目录入口和目标的差异记录，避免维护数份易过期的相同说明。
