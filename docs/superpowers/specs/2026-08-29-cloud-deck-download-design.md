# 云端牌组下载与自动安装设计

> 归档状态：这是一次性历史设计/执行记录，不是当前路线图、待办列表或操作手册。未勾选项不表示仍未实现；当前事实请查阅 [文档导航](../../README.md)、[开发状态](../../DEVELOPMENT_PLAN.md)、[当前架构](../../architecture.md) 和实际源码/测试。


日期：2026-08-29

## 目标

在不自建业务服务器、软件无需登录账号的前提下，让用户从应用内浏览作者托管的牌组，下载 `.apkg` 后立即导入。入口有两个：新安装首次进入首页时的引导弹窗，以及首页右上角“新建牌组 → 导入牌组 → 软件云端牌组”。

当前只实现公开牌组下载，同时为后续兑换码牌组保留目录协议字段。托管管理凭据、网盘账号和上传密钥绝不进入客户端。

## 用户体验

### 首次启动

1. 首页检查本机 `cloud_deck_onboarding_completed` 偏好。
2. 未完成时优先显示云端牌组弹窗；它采用项目现有弹窗的磨砂遮罩、卡片、圆角、颜色与转场。
3. 弹窗加载远端 JSON 目录，显示牌组名称、说明、版本、预计大小与选择状态。
4. 用户可多选公开牌组并开始下载。牌组逐个下载、逐个导入，界面显示当前牌组与总进度。
5. 每个成功下载的 `.apkg` 立即调用现有导入后端安装；完成后刷新首页并展开新出现的父牌组。
6. 用户可以跳过。跳过或全部任务结束后写入首次引导完成标记；网络失败不会阻断首页，弹窗提供重试与跳过。
7. 旧的版本欢迎弹窗在云端牌组首次引导结束后再显示，避免两个全屏弹窗叠加。

### 手动导入

1. 首页右上角“新建牌组”菜单保持现有“新建牌组”和“导入牌组”。
2. 点击“导入牌组”后显示同款磨砂弹窗，询问“从本地导入”或“软件云端牌组”。
3. 本地导入继续使用现有系统文件选择器和现有数据迁移流程。
4. 云端牌组打开与首次引导相同的目录弹窗，但关闭它不会改变首次引导偏好。

## 托管协议

客户端只依赖一个可替换的 HTTPS JSON 目录地址。目录和 `.apkg` 可以放在 123Pan、GitCode、对象存储或任何能提供稳定 HTTPS 直链的国内第三方服务；更换托管方无需改 UI 与导入逻辑。

目录示例：

```json
{
  "schemaVersion": 1,
  "decks": [
    {
      "id": "english-basic",
      "name": "英语基础词汇",
      "description": "适合入门复习",
      "version": "1.0.0",
      "accessType": "public",
      "downloadUrl": "https://download.example.com/english-basic.apkg",
      "size": 1048576
    },
    {
      "id": "premium-demo",
      "name": "进阶牌组",
      "description": "后续开放",
      "version": "1.0.0",
      "accessType": "redeem_code",
      "downloadUrl": "",
      "size": 0
    }
  ]
}
```

约束：

- `schemaVersion` 当前必须为 `1`。
- `id` 在目录中唯一；不合法或重复条目被忽略。
- 公开牌组的 `downloadUrl` 必须是 HTTPS；允许第三方 API 使用不带 `.apkg` 扩展名的路径，文件下载后再校验 ZIP/APKG 文件头。
- `size` 可省略；存在时必须是非负整数，用于显示和下载后校验。
- `accessType` 为 `public` 或 `redeem_code`。兑换码条目可展示为锁定状态，但本版本不可选择。
- 目录地址暂未提供时，配置保持空值，弹窗明确提示“云端牌组源尚未配置”，本地导入仍可用。

后续兑换码功能会增加一个第三方兑换 API：客户端提交兑换码和牌组 ID，服务端验证后返回短时有效下载地址。当前目录模型已经预留访问类型，但不会把永久受保护直链或验证密钥放入安装包。

## 代码结构

- `model/云端牌组模型.ts`：纯 TypeScript 类型、JSON 解析与校验、格式化大小。不得导入 `@kit.*`，可由 Node 测试直接执行。
- `model/云端牌组配置.ts`：唯一目录地址配置点；当前允许为空。
- `model/云端牌组引导存储.ets`：首次引导偏好读写，失败静默降级。
- `backend/云端牌组服务.ets`：用 NetworkKit 获取小型 JSON 目录，用系统下载代理将大文件直接写入沙箱；公开 API 只暴露目录加载、单牌组下载及进度回调。
- `components/导入来源弹窗.ets`：仅负责本地/云端二选一。
- `components/云端牌组弹窗.ets`：目录、选择、锁定、空态、错误、下载进度和结果展示；不持有网络或导入逻辑。
- `pages/首页.ets`：协调首次弹窗顺序、加载目录、逐项下载、调用现有 `执行牌组导入`、刷新首页。

## 下载与安装状态

每个条目状态为 `idle`、`downloading`、`importing`、`success` 或 `failed`。批处理严格串行：下载一个、导入一个，再处理下一个，避免多个后端导入并发和多个大文件同时占用存储。

下载路径为应用沙箱 `filesDir/cloud-decks/<安全文件名>.apkg`。下载完成后检查文件存在、非空、ZIP/APKG 文件头，并在目录提供 `size` 时核对大小；随后交给 `执行牌组导入`。该函数成功或失败都会清理导入文件，因此失败不残留半成品；下载代理失败、暂停或连续 90 秒没有新增字节时，服务层也会结算并移除任务、清理目标文件。

一项失败不会阻止剩余选中项。全部完成后保留每项结果，成功项已经安装，失败项可重新选择重试。

## 错误与安全

- 目录未配置、超时、非 2xx、JSON 不合法、无有效条目分别显示可理解的本地化状态。
- 只允许 HTTPS 目录与下载地址，不跟随目录中的本地路径或 provider URI。
- 文件名只从牌组 ID 派生并清理危险字符，不能逃逸沙箱目录。
- 不记录完整下载 URL、兑换码、账号或密钥。
- 下载期间禁用关闭与重复提交，避免状态与文件生命周期中断。
- 首次引导失败可跳过，应用核心功能始终可进入。
