# 官方启动公告设计

> 归档状态：这是一次性历史设计/执行记录，不是当前路线图、待办列表或操作手册。未勾选项不表示仍未实现；当前事实请查阅 [文档导航](../../README.md)、[开发状态](../../DEVELOPMENT_PLAN.md)、[当前架构](../../architecture.md) 和实际源码/测试。


## 目标

为记得闪卡增加在冷启动和返回主页时检查的官方重要公告。公告内容存放在 123 云盘直链文件夹中，应用通过一个稳定的公开 HTTPS 长链读取结构化 JSON，再用 ArkUI 原生弹窗展示。发布新公告不需要重新发布应用，也不在客户端保存 123 云盘账号、Client ID、Client Secret 或上传令牌。

送达目标不是即时推送，而是：安装了支持版本、网络正常且 123 直链服务可用的用户，在冷启动时立即检查；发布后返回主页时立即检查或在距离上次检查满 10 分钟时补做一次检查。用户确认后，本设备不再展示同一公告 ID。

本功能只处理重要启动公告，不建设公告中心、历史列表、未读角标、推送通知、用户分群或阅读统计。

## 托管结构与稳定地址前提

123 云盘直链文件夹使用以下结构：

```text
/jidecards/
├── announcement.json
├── announcement.html       # 可选；仅在已配置静态网页托管与自定义域名时提供
└── assets/                 # 仅供详情页使用
```

`announcement.json` 是应用唯一数据源。客户端配置必须使用 123 云盘控制台为该文件实际生成的 HTTPS 长链，不得根据 UID、目录名或 CDN 主域名自行拼接地址。

上线前必须完成稳定地址验证：先上传停用态文件并记录长链，再以同名替换方式发布一份内容不同的测试文件，确认原长链仍返回新内容。若替换文件会改变长链，则普通直链不能作为可更新公告源，必须先改用已配置自定义域名的静态网页托管或其他能提供稳定 URL 的托管服务。

`announcement.html` 不是弹窗内容源，应用不会在内嵌 Web 组件中执行它；它只允许作为可选的“查看详情”外部网页，由系统浏览器打开。没有配置直链自定义域名和 HTTPS 静态网页托管时，本期只发布 JSON，`actionUrl` 保持为空。

应用运行时只执行匿名 HTTPS GET。开发者权益包及 OpenAPI 仅用于发布或替换静态文件，管理凭据只能存在于开发电脑或受控发布环境中。

## 公告协议

远端文件只承载一条当前公告：

```json
{
  "schemaVersion": 1,
  "announcement": {
    "id": "20260829-01",
    "enabled": true,
    "titleZh": "官方公告",
    "contentZh": "记得闪卡云端牌组服务现已开放。",
    "titleEn": "Official announcement",
    "contentEn": "Cloud decks are now available.",
    "publishedAt": "2026-08-29T18:00:00+08:00",
    "startsAt": "2026-08-29T18:00:00+08:00",
    "expiresAt": "2026-09-30T23:59:59+08:00",
    "minimumAppVersion": "2.0.0",
    "maximumAppVersion": "",
    "actionUrl": ""
  }
}
```

字段规则：

- `schemaVersion` 必须为 `1`。
- `announcement` 可以为 `null`，表示当前没有公告。
- `id` 必须非空，只允许 `A-Z a-z 0-9 . _ -`，最大 64 个字符；每次发布不同公告必须使用新 ID。
- `enabled` 必须为 `true` 才参与展示判断。
- `titleZh`、`contentZh` 必须非空，标题最大 80 个字符，正文最大 4000 个字符。
- `titleEn`、`contentEn` 可以为空；英文界面缺少英文内容时回退中文，不因翻译缺失丢弃公告。
- `publishedAt`、`startsAt`、`expiresAt` 必须为有效 ISO 8601 时间，且开始时间早于过期时间。
- `minimumAppVersion` 必须为合法的点分数字版本；`maximumAppVersion` 为空表示不设上限。
- `actionUrl` 可以为空；非空时必须是 `https://` 地址，弹窗才显示“查看详情”。按钮文案使用应用本地 i18n 资源，不接受远端自定义按钮文字。
- 忽略未知字段，拒绝类型错误、必填字段缺失或超过长度限制的数据。
- 响应体上限为 64 KiB，超过上限视为无效公告。

## 客户端模块

### `model/官方公告模型.ts`

纯 TypeScript 协议层，不依赖 `@kit.*`。负责解析 JSON、字段长度与 URL 校验、版本比较、时间窗口判断和语言选择。对外只产生“可展示公告”或 `null`，UI 不再重复业务判断。

### `model/官方公告配置.ts`

保存唯一公开 `announcement.json` 地址。客户端不得出现 123 云盘管理凭据。

### `backend/官方公告服务.ets`

使用 NetworkKit 请求公告 JSON。请求地址追加十分钟时间桶查询参数，例如 `?v=202608291800`，降低 CDN 旧缓存持续时间，同时避免每次检查都制造一个全新的缓存键。单次请求有独立的 2 秒墙钟总截止时间；连接与读取超时不能被误认为总截止时间。不重试，不阻塞后续启动流程。

服务只负责网络读取并调用模型解析，不持有 UI 状态，也不读写已读记录。

### `model/官方公告存储.ets`

使用现有 `jidecards_settings` Preferences 保存最近确认过的公告 ID。采用最多 32 项的有序 ID 列表，防止远端回滚到旧公告时重复展示；写入时去重并保留最近 32 项。

只有用户点击“我知道了”才写入 ID 并 `flush()`。展示前不写已读记录；应用被系统终止或用户强制关闭后，下次启动仍应再次展示同一公告。

### `components/官方公告弹窗.ets`

纯展示组件，沿用现有全屏磨砂遮罩、主题色、圆角和全屏转场。显示远端标题、正文、发布时间信息和以下操作：

- 主按钮“我知道了”：通知首页持久化已读并关闭弹窗。
- 可选按钮“查看详情”：当 `actionUrl` 合法且非空时交给系统浏览器打开；打开失败时显示本地化提示，公告保持打开。

系统返回键和遮罩点击均被消费，不能关闭弹窗，避免重要公告被误触跳过。弹窗不渲染远端 HTML，不执行远端 JavaScript。

### `pages/首页.ets`

首页只协调启动状态和弹窗顺序，不解析公告协议。启动顺序固定为：

```text
拉取并判断官方公告
  ↓ 没有可展示公告、请求失败或用户确认
首次云端牌组引导
  ↓ 已完成或用户完成引导
版本欢迎弹窗
```

公告判断需同时满足：公告有效、当前时间在展示窗口内、当前应用版本在目标范围内，并且公告 ID 不在本地已确认列表中。

首页维护公告检查协调状态：上次检查开始时间、是否有请求在途、是否有一个延迟检查任务，以及待展示公告。所有入口共用同一个协调方法，禁止并发请求和重复定时器。

检查时机固定为：

- 首页冷启动：立即检查，不受 10 分钟窗口限制，并保持“公告 → 云端牌组引导 → 版本欢迎弹窗”的首次启动顺序。
- App 从后台回到前台且主页位于前台：触发一次主页公告检查。
- 从学习页、统计页、设置页及其他导航目标真正返回主页：触发一次主页公告检查；不能只依赖 `onPageShow`，因为现有 Navigation push/pop 不保证触发 Entry 页的 `onPageShow`。
- 距离上次检查已满 10 分钟：立即请求。
- 距离上次检查不足 10 分钟：不立即请求，只安排一个在窗口届满时执行的延迟检查。
- 延迟检查执行一次后不继续周期轮询；只有下一次冷启动、回到前台或返回主页事件才会建立新的检查机会。

上次检查时间只保存在当前进程内，App 冷启动始终立即检查。公告请求在途时收到更多主页事件只复用该次检查，不发第二个请求。主页不可见、处于子页面或有不可安全打断的事务弹窗时不展示公告；有效结果可暂存，待真正回到主页且没有冲突弹窗时再展示。

公告可见时在 `onBackPress` 中优先消费返回事件。用户点击“我知道了”后立即更新内存中的已确认集合，即使后续主页事件再次触发检查，也不得在本次进程中重复展示同一 ID。

该机制保证的是“发布后发生主页返回事件的用户，通常立即、最迟约 10 分钟检查到”，不是服务端推送。用户发布后一直停留在主页且没有重新进入主页，不会触发无限轮询。

## 流量边界

- 发布用 `announcement.json` 应控制在 5 KiB 以内；64 KiB 只是客户端安全上限，不是建议大小。
- 每个运行中的客户端在频繁返回主页时最多每 10 分钟发起一次公告请求；冷启动检查例外。
- 主页保持不动时不持续轮询，避免常驻前台设备消耗直链流量。
- 公告请求消耗 123 云盘直链流量，但不调用客户端 OpenAPI，也不消耗 OpenAPI 上传 QPS。
- 运营时同时关注公告 JSON 与云端牌组下载的总直链流量；流量耗尽时公告读取按网络失败静默降级。

## 错误与降级

- DNS、TLS、超时、非 2xx、空响应、超大响应、无效 JSON 或协议校验失败：静默跳过公告；冷启动继续云端牌组引导与欢迎弹窗，后续返回主页检查不影响当前页面。
- Preferences 读取失败：按“未读”处理，允许展示公告。
- 用户确认后的 Preferences 写入失败：显示本地化提示，但仍关闭弹窗并继续启动，避免持久化故障阻断应用；由于没有成功保存，下次启动可能再次展示同一公告。
- 系统浏览器打开详情失败：显示提示但不关闭公告。
- 远端 `announcement` 为 `null`、`enabled=false`、未到开始时间、已经过期或版本不匹配：不展示，也不写已读记录。
- 公告服务不可用时单次检查绝不阻断应用超过 2 秒，也不影响本地学习、AnkiWeb 同步或已下载牌组。

## 发布流程

初始实现允许在 123 云盘中手动替换静态文件；后续发布工具可通过 OpenAPI 自动完成相同步骤：

1. 在本地校验 `announcement.json` 协议。
2. 上传或同名替换 JSON；普通直链模式下不上传 HTML，已配置自定义域名静态托管时才可同时发布详情页。
3. 使用客户端配置的同一稳定 HTTPS 长链并追加当前十分钟时间桶参数重新下载，验证状态码、响应大小、公告 ID 和解析结果。
4. 若平台提供直链缓存刷新，发布后刷新该文件缓存；无论是否刷新，仍以公开地址读回结果为准。
5. 验证成功后才视为发布完成，并观察直链流量余额。
6. 撤销公告时发布 `announcement: null` 或将 `enabled` 设为 `false`；不得复用已发布公告的 ID 表达另一条内容。

发布工具不属于本次客户端功能的实施范围，但公告协议和公开目录结构必须为它保留稳定接口。

## 测试与验收

### 模型测试

- 解析完整中英文公告。
- 英文缺失时回退中文。
- 拒绝错误 schema、非法 ID、无效发布时间或时间窗、倒置时间窗、非法版本、非 HTTPS 详情地址、超长标题和正文。
- 验证开始时间、过期时间、最小版本、最大版本和未知字段兼容。

### 存储测试

- 未确认公告返回未读。
- 确认后同一 ID 不再展示。
- 重复确认不产生重复项。
- 超过 32 项时只保留最近 32 项。
- 写入失败返回失败结果，首页仍能关闭弹窗并继续启动。

### 服务与流程契约测试

- 公告地址只存在于配置文件，源码中不存在管理凭据。
- 请求包含十分钟时间桶，且有独立的 2 秒墙钟总截止时间。
- 网络或解析失败继续执行原启动流程。
- 启动顺序为“官方公告 → 云端牌组引导 → 版本欢迎弹窗”，弹窗不会重叠。
- 冷启动立即检查；回到前台和从各导航目标返回主页时进入同一检查协调器。
- 10 分钟内的重复主页事件只建立一个延迟检查；请求在途时不并发；延迟检查后不持续周期轮询。
- 返回键不能关闭公告，冲突弹窗存在时公告延后展示。
- 只有“我知道了”会触发持久化和关闭；持久化失败也不得阻断启动。

### 真机验收

- 发布一条匹配当前版本的公告，首次冷启动出现，确认后再次启动不出现。
- 更换公告 ID 后再次出现；恢复旧 ID 时不重复出现。
- 发布新 ID 后从学习页、统计页、设置页返回主页，立即或在上次检查满 10 分钟时出现。
- 10 分钟内连续多次返回主页只产生一次实际请求；延迟检查完成后不自动持续轮询。
- App 从后台回到前台且主页可见时遵循同一 10 分钟规则。
- 验证深色模式、中英文、长正文滚动和窄屏布局。
- 断网、慢网、无效 JSON 和静态托管 404 时，应用在最多约 2 秒后继续进入原启动流程。
- 有详情地址时系统浏览器能够打开静态页面；无详情地址时不显示详情按钮。

## 非目标

- 不保存公告历史，不提供公告中心或设置入口。
- 不做推送通知、角标、阅读统计、账号同步、灰度分群或服务端脚本。
- 不承诺对离线设备、旧版 App、流量耗尽或 123 服务异常时即时送达；恢复条件后需再次发生冷启动或主页返回事件。
- 不在客户端调用 123 云盘管理 API，不上传用户数据。
- 不把公告并入 `cloud-decks.json`，避免公告与牌组目录故障相互影响。
