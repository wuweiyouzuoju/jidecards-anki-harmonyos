# Agent 对话式任务配置、澄清与统一折叠设计

> 归档状态：这是一次性历史设计/执行记录，不是当前路线图、待办列表或操作手册。未勾选项不表示仍未实现；当前事实请查阅 [文档导航](../../README.md)、[开发状态](../../DEVELOPMENT_PLAN.md)、[当前架构](../../architecture.md) 和实际源码/测试。


> 历史设计说明：2026-09-04 用户确认的现行交互见 [Agent 2.0 实施约定](../../agent-2-design.md#澄清的对话呈现)。本文中的澄清自动折叠、“已确认”标题及共用工具外壳已被替代：澄清显示普通问题，回答后移除回答控件，上一段保留澄清工具记录，按简洁版/实验版默认收起/展开；底层协议和状态机仍保留。开局配置也沿用原有直接显示的选择控件。

**日期：** 2026-08-31

**状态：** 已实施（隔离分支 `feature/agent-conversational-clarification`）

**范围：** AI 制卡、AI 改卡、运行时澄清、会话历史、工具过程折叠

## 1. 目标

把 AI 制卡页顶部固定的“目标牌组 / 笔记类型”表单改为对话中的本地助手引导气泡。用户在气泡中完成必要配置、在输入区填写材料或要求，满足发送就绪条件后再把完整任务一次性交给 Provider。

Agent 在制卡或改卡过程中遇到会实质改变结果、范围或风险的歧义时，可以暂停当前任务并提出结构化澄清。用户回答后，澄清项自动折叠，Agent 在同一逻辑会话中继续执行。

澄清项和工具调用统一使用同一种对话折叠外壳、状态文案、箭头和动画，避免页面同时存在多套展开/折叠语言。

## 2. 已裁定方案

采用“本地对话式前置配置 + Provider 运行时澄清 + 统一对话折叠组件”。

### 2.1 放弃的方案

1. **继续保留顶部固定选择栏**：实现最小，但配置与对话割裂，占用固定纵向空间，也无法承载后续数量、标签等任务选项。
2. **由模型先询问所有配置**：对话感最强，但打开页面就需要一次付费网络请求；牌组和笔记类型还可能被模型误写或误选，稳定 ID 与权限边界不可靠。
3. **选项点击后立即调用 API**：步骤少，但容易误触，也无法让用户在选项之外补充材料或要求。

选择的方案不要求 Provider 参与已知的本地配置，只在用户明确发送任务后联网；运行期只有真正阻断任务的歧义才触发澄清。

## 3. 产品交互

### 3.1 本地助手引导气泡

进入新建会话时，客户端立即生成一条 `local_setup` 类型的助手气泡。它看起来位于 AI 一侧，但不是 Provider 返回内容，不计费，也不写入 Provider 消息历史。

制卡模式的气泡包含：

- 目标牌组：必选，保存结构化 `deckId` 和显示名称。
- 笔记类型：必选，保存结构化 `notetypeId`、字段能力和显示名称。
- 引导文案：“选择完成后，请在下方粘贴学习材料或描述制卡要求，我会按照这些设置生成卡片。”
- 可扩展的非必填项入口：生成数量、标签等不在本次首版强制加入。

不再因为列表存在内容就静默选择第一项。只有导航入口明确携带目标牌组，或用户已有明确保存的选择时才允许预填，并必须在气泡中清晰展示。笔记类型不能仅凭本地化名称推断能力，继续使用后端返回的真实 kind、字段和 cloze 字段序号。

改卡模式使用同一种本地助手气泡，但内容根据入口变化：

- 从学习页或浏览页进入：展示只读的当前卡片/已选笔记范围，用户只需填写修改要求。
- 从无预选对象的首页入口进入：提示用户描述目标和修改要求，Agent 可在发送后使用受控搜索工具定位对象。
- 改卡不强制选择目标牌组或笔记类型；只有任务本身要求迁移牌组或笔记类型时，才由 Agent 查询真实候选并按风险规则提出草稿或澄清。

### 3.2 发送就绪条件

制卡模式同时满足以下条件后，发送按钮才进入可用状态：

1. 目标牌组有效；
2. 笔记类型有效且字段能力已经加载；
3. 用户输入去除首尾空白后不为空；
4. 当前 Provider 的 API 密钥、地址和模型配置有效；
5. 当前没有正在执行或等待提交的请求。

未就绪时，在本地引导气泡或输入区附近显示最先缺失的条件。不能先允许点击，再用异步错误提示用户缺少牌组或笔记类型。

如果牌组或笔记类型在选择后被删除或能力加载失败，应立即把对应选择标记为无效、重新展开本地配置并禁用发送。

### 3.3 正式发送

点击发送时生成一个不可变的任务快照，至少包含：

- 会话 ID 与任务模式；
- `deckId`、牌组名称；
- `notetypeId`、笔记类型名称、字段列表、kind 和 cloze 字段序号；
- 用户输入的学习材料或修改要求；
- 当前入口上下文与稳定 ID 授权范围；
- 本轮批量限制和用户明确要求的数量。

用户气泡显示配置摘要和用户输入，便于回看；Provider 输入使用结构化快照构建，不能再从气泡显示文字反向解析 ID。

发送后本地配置气泡折叠为一行摘要，例如“目标：中国 · 笔记类型：填空题”。用户可以展开查看或修改下一轮配置，但修改不能改变已经生成的草稿及其保存目标。

## 4. 运行时澄清

### 4.1 触发条件

只有以下阻断性情况可以暂停并澄清：

- 两种合理理解会生成明显不同的卡片；
- 制卡材料、目标或数量存在无法安全推断的冲突；
- 改卡对象或影响范围不明确；
- 操作涉及删除、笔记类型迁移、模板/CSS 或其他高风险边界；
- 继续执行会要求模型虚构不存在的数据或权限范围外的稳定 ID。

措辞、格式等非关键偏好使用合理默认值并交付可编辑草稿，不应频繁打断用户。

### 4.2 结构化澄清请求

新增受控的 `request_clarification` Agent 工具，并由 Runner 将合法调用转换为终止当前 turn 的 `awaiting_clarification` 结果。请求必须包含：

- 稳定的 `clarificationId`；
- 一个明确、单一的问题；
- 2—4 个互斥选项，每项包含稳定 ID、短标签和可选说明；
- 可选的推荐项 ID；
- 是否允许补充自由文本。

该工具不读取或写入 Anki 数据。参数通过既有工具 Schema 边界校验；无选项、重复 ID、超长文本或超过四个选项均返回受控工具错误。

Runner 收到合法澄清请求后：

1. 结束当前 Provider 工具循环；
2. 返回 `awaiting_clarification`，而不是无草稿错误；
3. 保留当前任务快照和已完成的只读工具结果；
4. 不创建、不保存任何写草稿；
5. 页面把当前执行气泡标记为“等待你的回答”，并追加独立澄清气泡。

制卡模式现有“本轮必须产生合法草稿”的完成契约增加一个合法例外：`awaiting_clarification` 是暂停态，不是成功完成，也不是 `agent_no_valid_draft`。

### 4.3 回答与继续

待回答的澄清气泡始终展开，用户先选择一个选项，可以补充文字，然后点击“继续”。点击选项本身不立即调用 API。

继续时：

1. 锁定选项和补充文字，防止重复提交；
2. 把回答显示为用户消息；
3. 把澄清问题、选项语义、用户选择和补充文字加入同一逻辑会话的 Provider 上下文；
4. 使用原任务快照重建本轮 `AgentScope`，重新校验稳定 ID；
5. 启动新的有界 Agent turn，继续生成草稿或执行查询。

同一时间最多存在一个待回答澄清。用户取消任务或开始新会话时，未解决澄清随所属任务一起终止。

## 5. 澄清气泡生命周期

澄清状态固定为：

```text
pending → submitting → resolved
                  └→ submit_failed → pending
pending → cancelled
```

- `pending`：保持展开并允许选择、补充和继续。
- `submitting`：控件禁用，防止重复请求。
- `resolved`：自动折叠，标题显示“已确认：<选择摘要> ✓”。
- `submit_failed`：恢复原选择和补充文字，保持展开并显示错误，可重试。
- `cancelled`：折叠为“澄清已取消”，不允许继续旧任务。

解决后的气泡仍可手动展开查看原问题、全部选项和最终回答，但控件只读。用户若要更正，应发送新的用户消息，不能篡改已经进入后续推理的历史答案。

## 6. 统一对话折叠

新增一个仅用于 Agent 对话内容的公共折叠外壳。它复用当前工具详情已经确认的视觉语言：

- 标题、状态和 `▼` 箭头位于同一行；
- 展开角度 0 度、折叠角度 -90 度；
- 150ms `Curve.EaseOut` 旋转；
- 使用对话区域现有卡片底色、边框、圆角和间距；
- 整行可点击，交互控件区域自身点击不能误触折叠；
- 展开状态由宿主消息保存，事件更新不得覆盖用户手动选择。

首版统一以下内容：

1. 本地任务配置气泡：未完成配置时展开，正式发送后自动折叠；
2. 澄清气泡：待回答时展开，解决或取消后自动折叠；
3. 工具调用：继续默认折叠，运行、完成或失败状态更新不得重置用户展开状态。

工具调用不再自己维护另一套标题行、箭头和动画，只提供标题、状态和详情内容给公共折叠外壳。思考摘要和来源的内容顺序仍保持“正文 → 思考 → 工具 → 来源 → 草稿”，本次不改变其语义或 Provider 真实性边界。

折叠只影响本地渲染，不删除消息、工具审计、澄清问题或用户答案，也不改变下轮 Provider 上下文。

## 7. API 会话与上下文

继续沿用当前客户端维护会话的方式：每次发送都是独立 API 请求，页面从本地历史重新构建必要的用户/助手消息；不依赖 Provider 侧永久会话或 `previous_response_id`。

上下文规则：

- `local_setup` 引导气泡及其控件文案不发送给 Provider；
- 正式任务快照作为首条用户任务发送；
- Provider 提出的澄清问题进入助手历史；
- 用户选择和补充进入用户历史；
- 已解决气泡即使在 UI 中折叠，问题与回答仍保留在 Provider 上下文；
- API 密钥、授权头、确认令牌、原始隐藏 reasoning 和媒体二进制继续禁止进入本地历史或 Provider 消息；
- 长会话仍遵守现有脱敏、截断和安全限制，不为了恢复折叠状态保存敏感内容。

运行时澄清工具调用不跨请求重放为悬空的 function call。当前 turn 以 `awaiting_clarification` 结束；下一次请求用普通的助手问题与用户回答重建语义连续性，再开始新的工具循环。

## 8. 历史存储与恢复

会话历史增加结构化但可选的数据：

- 当前任务配置快照；
- 消息类型；
- 澄清 ID、问题、候选项、推荐项、自由文本能力；
- 最终选择、补充文字和生命周期状态；
- 对话折叠状态。

旧历史没有这些字段时继续按普通文本消息恢复。新历史恢复规则：

- 已解决或已取消澄清默认折叠；
- 未回答澄清默认展开并恢复可选状态；
- 工具追踪继续默认折叠；
- 不恢复旧草稿、确认令牌或已经失效的 Provider 请求；
- 恢复待回答澄清前重新验证所属任务配置和入口稳定 ID；失效时把澄清标记为取消，并要求用户重新发起任务。

## 9. 组件与边界

实施固定拆分为以下职责单一的单元：

- **对话折叠外壳**：只负责标题、状态、箭头、动画和展开内容插槽。
- **本地任务配置卡**：负责牌组/笔记类型选择和发送就绪提示，不直接请求 Provider。
- **澄清卡**：负责选项、补充文字、继续提交和只读回看。
- **澄清协议模型**：纯 TypeScript 类型、Schema 校验和状态转换，不依赖 HarmonyOS Kit。
- **Runner 暂停结果**：让工具循环明确返回 `awaiting_clarification`，不在 UI 层猜测模型正文。
- **会话存储映射**：负责结构化澄清和折叠状态的脱敏持久化与恢复。

这些单元不得绕过既有 `AgentScope`、`AgentDraftExecutor`、草稿确认或高风险二次确认边界。澄清本身永远不能执行写操作。

## 10. 错误与边界行为

- Provider 在澄清前已经返回部分正文：正文保留，执行气泡标记等待，不得伪称已经完成制卡。
- 澄清提交网络失败：保留用户选择，恢复待回答状态，不追加重复用户消息。
- 用户离开页面：取消当前网络请求；已经落盘的待回答澄清可在历史中恢复。
- 用户修改配置：只影响下一次正式任务，不能改变旧草稿的目标牌组或笔记类型。
- 配置失效：展开配置气泡、禁用发送并指出失效项。
- 工具调用失败：仍使用统一折叠外壳，标题状态显示失败，展开后保留经过脱敏的诊断。
- 高风险改卡：澄清不能替代草稿确认或二次确认；两者是不同安全阶段。

## 11. 测试与验收

### 11.1 纯模型与 Runner 契约

- 合法澄清请求进入 `awaiting_clarification`，不会触发 `agent_no_valid_draft`。
- 选项数、唯一 ID、推荐项和文本长度校验准确。
- 同一时间不能登记两个待回答澄清。
- 回答后新 turn 包含原问题、最终选择和补充文字。
- 重建 `AgentScope` 后，失效稳定 ID 不能继续使用。
- 澄清路径不产生 `ChangeDraft`，也不调用 `AgentDraftExecutor`。

### 11.2 UI 契约

- 制卡页顶部固定目标牌组/笔记类型区域消失，选择器位于本地助手气泡。
- 缺少任一必要项时发送按钮禁用并显示缺失条件。
- 引导气泡不进入 Provider 输入；发送后的用户气泡显示任务配置摘要。
- 待回答澄清保持展开，解决后自动折叠并可只读回看。
- 澄清和工具调用使用同一折叠外壳、箭头角度和 150ms 动画。
- 工具状态更新不覆盖用户手动展开状态。
- 所有新增用户可见文案同时提供中文与英文 i18n 资源。

### 11.3 历史与恢复

- 已解决澄清恢复为折叠，只读内容完整。
- 未回答澄清恢复为展开；上下文失效时安全取消。
- 折叠与展开不改变下一轮 Provider 输入。
- 旧历史仍可作为普通文本对话打开。

### 11.4 完整验证

- 运行新增聚焦契约测试和完整 `npm test`。
- 因为改动跨页面、模型、Runner 和历史存储，按 Structural 工作流运行 `npm run build:app`。
- 使用 `install -r` 覆盖安装模拟器，验证普通问答、填空、自定义笔记类型、改卡入口、澄清暂停/恢复和历史恢复。
- 不执行 `uninstall`；实体设备不在线时只报告模拟器结果，不宣称真机通过。

## 12. 非目标

- 不把本地牌组/笔记类型选择交给模型决定。
- 不创建 Provider 侧长期会话依赖。
- 不允许一个澄清问题同时选择多个互斥答案。
- 不让澄清绕过草稿确认、高风险二次确认或基线冲突检查。
- 不改变 Anki Rust、protobuf、NAPI ABI、数据库 schema 或调度算法。
- 本次不新增图片遮盖创建、媒体二进制上传或历史重命名功能。
