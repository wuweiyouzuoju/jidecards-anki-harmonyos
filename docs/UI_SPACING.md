# 页面间距与验收

尺寸唯一入口：[应用尺寸](../entry/src/main/ets/utils/应用尺寸.ets)。密度偏好与调用边界见[界面文档](development/appearance.md)。

## 必须相等的四段

| 标记 | 测量边界 |
| --- | --- |
| a | 系统状态栏时间（如9:49）的实际文字下缘 → 更多/新建牌组按钮上缘 |
| b | 顶部按钮下缘 → 今日进度卡片上缘 |
| c | 今日进度卡片下缘 → 第一张牌组卡上缘 |
| d | 相邻牌组卡之间 |

目标 **a=b=c=d**，宽版12vp，窄版8vp。不是各自缩小不同数值；a也不是安全区边界或胶囊按钮内的文字。各页外侧水平留白仍12vp，卡片内部16vp。

## 实现与平台限制

`页面分组间距` 是四段的唯一间距值；`页面内容顶部间距` 返回相同值。顶栏的高度为 `pageToolbarTop + 按钮高度44`，底padding为0，避免b重复叠加。菜单使用 `pageContentTop`，与首卡上缘对齐；公共菜单收到的是最终坐标，不再次应用密度补偿。浏览页搜索区、筛选区、首张结果卡和结果卡之间都由 `页面分组间距` 产生边界，筛选区不再额外叠加底部数值。固定开始学习/显示答案操作区使用 `操作区顶部间距` 和 `操作区底部间距`；后者为页面底部留白加导航条高度，导航条不存在时仍保留同档页面留白。

系统窗口只提供避让区矩形，不提供时间字形的像素边界。`statusTextBottomInset=6vp` 为2026-09-27用户截图的初始估计，尚未在设备上校准；并非平台保证，不可声称适用于所有字体与设备。代码显式从安全区底部扣除这个光学估计，再增加公共间距a；无状态栏时文字下缘钳制为0。后续设备测量若不符，只修正这一入口并复验两档，不在页面分别补偿。

估计依据：原图 `Screenshot_2026-09-27T004431.png` 为1320×2856px；时间深色字形下缘约116px，按钮边框上缘约164px、下缘约317px。若对应44vp按钮，则像素比例约3.48px/vp，原a约13.8vp；结合原顶栏8vp上内边距，推算安全区内文字下方留白约5.8vp，初值取6vp。截图包版本和实际vp比例未核实，所以这是可追溯的估计，不能冒充系统测量。

覆盖首页、设置、统计、浏览、学习、预览、添加笔记、提醒、Agent及既有顶部菜单。表单标签、聊天气泡、闪卡HTML、日历格子、白板和全屏编辑器的工具栏保留各自语义；固定底部操作栏保留既有安全区规则。

## 验证

新增/编辑笔记的滚动正文也使用 `页面分组间距`：笔记类型行到首张字段卡、相邻字段卡、字段卡到标签区由宿主 Column 提供一次间距，宽版12vp、窄版8vp。`NoteFieldCard` 只拥有卡片内部16vp留白，不叠加卡片外 margin；字段标题、输入与格式工具仍沿用编辑器内部间距。顶栏、正文顶部、左右12vp页面留白和系统安全区继续使用既有公共入口。两档和有/无状态栏的表达式检查见 `ui-shell-contract.test.mjs`，实际设备像素验收仍需单独完成。

`tools/tests/ui-shell-contract.test.mjs` 执行真实尺寸函数和顶栏表达式，检查两档及往返切换的a/b/c/d（a使用光学估计），锁定已统一页面与菜单的接线。完整入口 `npm run verify`。

设备由用户操作。验收应以实际系统时间字形及控件外缘测量四段，并检查宽/窄往返、首帧、系统字号、旋转、折叠、菜单打开与关闭。编译与数学回归不能证明系统文字像素位置；未完成此项前不能报告四段已在真机精确相等。
