# 玻璃融合：长期实验与验收

本页是当前任务入口。目标是完整播放、自然形变、材质连续、可靠开关；代码存在、平均耗时下降或某一张截图正常都不能判为完成。任务状态：**实验中，尚未通过最终视觉验收**。

## 单一实现与实验边界

- `src/core/GlassFusion.ts`：解析距离场、融合、裁切和折射网格。
- `src/harmony/shared/GlassBackdrop.ets`：现有背景会话、渲染节点、显示帧回调；不在产品复制算法。
- `examples/GlassFusionLab.ets`：独立背景、明暗、128/256/512预算、展开/收起/反向/销毁。背景不含触发按钮和控制台，避免自采样干扰；由build:harmony同时编译。编译样例不表示已安装真机。
- `tools/glass-fusion-experiment.mjs`：执行真实几何，输出可逐帧预览HTML与JSON。不是玻璃GPU渲染或设备FPS模拟器。
- `tools/glass-fusion-device-report.mjs`：只读收集真机日志与包信息；报告默认保持视觉/输入验收pending，禁止凭性能日志自动通过。
- 闪卡首批入口：首页更多/新建的AnchoredMenu。其余入口仍沿用锚点缩放，关闭仍走原业务；不冒充全部弹窗已完成材质融合。

## 每轮实验

1. 记录源码哈希、HAR哈希、HAP、签名类型、设备/窗口尺寸、明暗、动作档位与实验名称。不同源码、设备、采样策略的结果不得混为同一批。
2. 先跑几何对比（左/右/向上菜单、宽屏对话框，128/256/512单元），保留report.json和preview.html。检查端点误差、折射三角形方向、运动中拓扑变化和轮廓抖动。
3. 构建HAR与样例HAP，仅同步目标消费者，再构建测试签名产品。设备只能覆盖安装，禁止卸载/清数据。
4. 性能批次不同时录屏/截图，避免采集污染；同一场景先预热，再至少20次完整往返。收集几何CPU、draw命令CPU、VSync回调间隔分布、完成原因。GPU耗时需另行系统跟踪，不把draw命令提交耗时写成GPU耗时。
5. 视觉批次独立录制：正常速度、慢放、起点/连接/终点。检查按钮按下到启动是否闪亮、原按钮是否重复绘制、背景是否含自身、材质是否突然换色、边缘是否锯齿/断线、文字是否突然出现或遮挡。
6. 输入检查：原按钮再点收起、外部点击、系统返回、动画中反向、快速开关、叠层、后台/返回、旋转/改尺寸、明暗切换、减少动效。不能为了等待动画改变业务写入/草稿/忙碌守卫。
7. 所有维度通过后才请求用户视觉验收。失败样本必须保留并说明原因，不能通过删掉慢帧、延长时长、加模糊或跳到终态获得通过。

## 验收目标与当前基线

以下是实验目标，不是已达到的承诺。60Hz场景至少20轮完整播放，不允许因CPU超预算直接跳到终态；几何+绘制提交CPU的P95目标小于4ms；回调间隔P95目标不超过一个显示周期加1ms，无连续超过两个周期的停顿。更高刷新率按实际周期另测。端到端首帧、GPU合成与输入延迟另作证据，不能从这些数值推导。

视觉与交互是独立门槛：不闪、不双影、不跳色、轮廓平滑、原按钮可收起。用户未接受的效果，无论性能数值如何均保持实验中。

| 实验 | 实际证据 | 结论 |
| --- | --- | --- |
| 初版1024单元、重复三角形取样 | 平板每次3次更新后frame_budget，未完整播放 | 失败，不能交付 |
| 256单元、共享取样缓存 | 2026-10-31 14:55后9次finished，合计1次回调间隔超过25ms；几何均值约4ms | 性能基线，视觉未接受 |
| 固定基础网格、索引共享顶点、复用交点/位置/纹理缓冲、缓存画笔/路径 | 第4轮增加边缘求根及按0.15vp误差细化，12组端点误差<0.15vp、无回折；平板20次完整open，late25=0，CPU均值约5.38ms、峰值10ms | 播放完整，但CPU未达到目标，继续优化 |
| 缓存圆角矩形距离场常量、热循环移除可变参数hypot、复用RenderNode.frame | 第5轮几何检查通过，待平板相同批次比较；新增反向关闭协议 | 实验中 |

运行中CPU超预算跳终态已从SharedGlassFusion移除；准备失败、无有效几何、后台和减少动效属于不同生命周期语义，不得把它们与性能跳帧混淆。日志和失败状态仍保留，报告不把未完整播放当成功。

## 架构实验与参考

已读[shuding/liquid-glass](https://github.com/shuding/liquid-glass)的SVG位移实现（参考提交a2d2e847f793430e3409a52927af815a23f4d372），采用距离场到位移的思路；它不是鸿蒙原生GPU方案，不能直接当性能结论。[liquid_glass_widgets](https://github.com/sdegenaar/liquid_glass_widgets) README提供shader预热和独立渲染入口思路，尚未完成其着色器源码审查，不能写成已移植或已验证。当前没有复制这些项目源码。

SDK检查：现有ArkTS Drawing公开接口没有直接可用的运行时片元着色器入口；本机官方文档“自定义渲染(XComponent)”确认可经TEXTURE + EGL/OpenGLES合成透明自绘内容。因此GPU距离场候选需要独立原生渲染适配、纹理传输和资源生命周期，不能通过换一个曲线宣称GPU化。

下一阶段按顺序比较：先用同一场景验收池化网格；如CPU/边缘稳定性仍不达标，制作独立XComponent TEXTURE原型，验证纹理只上传一次、单一SDF轮廓和透明合成，再决定替换。GPU路线必须测冷启动编译、透明混合、视口/密度、上下文丢失、前后台与销毁；产品界面不作为未验证GPU实验的唯一试验台。


## iOS 实录与复刻依据

本机iPhone17/iOS27的现有闪卡应用使用系统原生Menu。新增只读UI测试`testGlassMenuReferenceRecording`，各打开/关闭更多与新建3次；不创建、修改或清理卡片。simctl连续录制51秒，测试1项通过，首个更多区间解出139个实际视频帧，并生成时间标注接触表。观察：按钮表面连续变为较圆的扩大轮廓，再收敛成菜单；文字在几何接近终态时出现；关闭回到触发点，源按钮图标恢复。原生菜单覆盖触发位置，而当前鸿蒙产品保留按钮下方菜单定位，不能以“复刻”名义改变已确认的几何与取消语义而不验收。

用户已明确收回采用反向效果。AnchoredMenu保持同一SharedGlassFusion，expanded反向后完成才调用原onClose；外部点击和返回只关闭，重复点击触发按钮可中途反向。其他业务选择/导航仍由原拥有者立即执行，未为动画延迟写入或取消守卫。

### 常驻按钮内圈（2026-11-16）

平板44vp按钮内的旧10vp cached环带形成明显的第二圈。`GlassRenderNode.clipMaterialInterior` 将常驻缓存折射限于1vp外沿；原生宿主继续拥有整面底色与模糊，cached不重复绘制tint，完整菜单/融合绘制不受影响。`tests/glass-capture.test.mjs` 验证密度换算后的真实裁切、路径复用和贴边半圆两侧；用户显式边线仍归产品的SurfaceBorder控制。闪卡使用重建HAR及同步测试快照，其他产品未在本轮安装。

2026-11-16：原生背景替代筛选侧栏的尝试已撤销：它消除了低清快照颗粒，却丢失用户要求的折射与边缘卷曲，不符合材质一致性，不能作为修复结论。侧栏恢复公共完整光学路径。弹窗底色合并同次drawVertices的缓存ColorFilter及常驻控件去重复描边保留；最低模糊度下大面积纹理清晰度仍待解决。

后续修正：完整折射面板在最低模糊度使用原像素采样，普通预热/常驻控件仍512px预算；取可见光学消费者矩形并集加36vp边缘，截图同时按区域裁切。保留完整源几何独立于采样矩形，拒绝缩放不足、位置/尺寸或菜单覆盖范围失效的缓存。大面板面积超过180000vp²时保留静态终态折射并整体淡入，小菜单继续融合，避免原像素整屏逐帧光栅化。产品DialogFrame采样ID移出灰色遮罩，子菜单透明源与未压暗父源合成，避免跨出弹窗的部分再次染灰。实机小菜单两次融合采样为15帧、帧间隔16.67ms、绘制均值约4ms、峰值5–6ms；这是渲染日志，不代表包括采样在内的总打开延迟。

2026-11-17：用户继续复现任意颜色的局部/整面染色和打开迟缓，前批截图不得外推为已解决。BackdropSession补齐同窗口背景会话链，透明父正文→透明页面→根背景逐层合成；递归裁切保留调用方分辨率，拒绝循环来源。冻结父场景的清晰原图覆盖目标时只复制裁切，不重复截图页面和根背景。新完整光学消费者拒收已失效的旧缓存；任意RGB且alpha=0的底色直接跳过滤色器。产品根背景在首个弹层打开时暂停彩雾并失效运动帧，最后关闭恢复，避免静态纹理与运动背景不一致。逻辑/合成测试与HAR/HAP编译不能代替真机确认；本批平板连接已断开，实际染色及总打开耗时尚未验收。
