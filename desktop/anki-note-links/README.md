# 双链引用 · JideCards 互通版

保留提供资料中的“我引用／引用我”、全局显示文本富文本编辑、搜索、拖动排序和预览返回逻辑。
重写数据持久化：完整关系随笔记字段同步，不再依赖电脑本地 `data.json`。

## 安装与迁移

1. 保留旧插件目录和 `user_files/data.json`，在 Anki 的插件管理中停用旧插件。
2. 安装本包的 `jide_note_links.ankiaddon`，重启 Anki。
3. “工具 → 双链引用 → 迁移旧版引用…”选择旧 `data.json`。迁移先创建 Core 备份，准备关联字段和背面模板，再批量写入完整关系。
4. 完成 Anki 同步，再在支持此协议的 jidecards 同步。目标笔记必须已在本地；单牌组包不会自动携带牌组以外的目标。
5. 电脑可从复习卡面悬浮入口、浏览器右键或编辑器“关联”按钮建立关系。鸿蒙可在新增/编辑页点击半圆轮盘外圈“引用卡片”，搜索、预览并确认，正文与引用随笔记一起保存；取消编辑不写入。

普通笔记类型无需预先准备字段或模板。正文引用使用标准 HTML 链接，每一处文字独立；保存钩子把完整关系写入现有字段的隐藏注释，运行时生成双向列表。“准备所有笔记类型”保留为旧模板兼容工具。两端都须使用本次新版，电脑插件提供正文点击预览与保存关系维护。

再次迁移不会覆盖新版字段，防止已在鸿蒙删除的引用被旧索引复活。
新版与旧版不应同时启用。原安装包和旧 JSON 始终保留；不把旧 JSON 直接删除或自动覆盖。
该版本不自动把新版字段回写成旧插件 JSON，回到旧插件前应保留当前集合备份。

## AI 接手入口

| 文件 | 职责 |
| --- | --- |
| `__init__.py` → `host.py` | 注册、菜单、受限消息路由、迁移入口 |
| `domain.py` | 无 Anki/Qt 的协议、迁移字段替换 |
| `repository.py` | 唯一 Anki 数据边界，批量 Core 更新 |
| `store.py` | 原编辑器的内存适配；同步/撤销/导入/切换配置后失效，不持久化第二份关系 |
| `mirror.py` | 原卡面 HTML 样式和受影响笔记镜像刷新 |
| `dialog.py` / `search.py` / `helpers.py` | 原交互分离成窗口、查询与显示辅助职责 |
| `card_inject.py` / `web/` | 原卡面入口、富文本编辑资源；点击预览使用 GUID |

完整协议和鸿蒙入口见 [开发文档](../../docs/development/note-links.md)。
从仓库根目录运行 `python -m unittest discover -s desktop/anki-note-links/tests -v`；跨语言和生产 Service 行为测试为 `tools/tests/note-links.test.mjs`。
从仓库根目录运行 `python tools/package-note-links.py --output <输出目录>`，只打包源码/资源，不携带 `user_files`、真实收藏库或密钥。

## 来源与行为边界

界面资源、搜索行为和卡面样式来自用户提供的 `mnemonic_links_插件资料_20261021.zip`，原始包 SHA-256 记录在交付清单。
这些原界面模块保留原注释；数据协议、存储适配、迁移、鸿蒙连接和验证为此互通实现。
电脑仍使用 Anki 的 PyQt/WebView，鸿蒙使用 jidecards 原生组件，不承诺两个平台逐像素一致。
同一笔记两端同时离线改动仍遵循 Anki 原有冲突处理；切换设备前后同步。
